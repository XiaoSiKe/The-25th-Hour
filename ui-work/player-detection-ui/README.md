# 第二十五小时检测 UI 方案

本文记录 `第二十五小时 · 建筑生模拟器` 的轻量监测屏原型方向。它面向项目方 / 开发者查看匿名概况和轻量游戏信号，不是玩家游戏内入口，也不定义玩法、数值、结局或排行榜计分规则。

正式数据契约见 [`../../docs/player-detection-monitor-contract.md`](../../docs/player-detection-monitor-contract.md)。

## 已确认方向

- 页面名称：第二十五小时 / 建筑生模拟器。
- 英文辅助名：THE 25TH HOUR · ARCHITECTURE STUDENT SIMULATOR。
- 使用对象：项目方 / 开发者。
- 页面形态：单页纯前端原型，后续通过数据适配层读取真实聚合数据。
- 风格：黑白极简像素风，少量灰度，固定深色模式。
- 资产：左侧使用 `没有退路的选择——一条最孤独之路` 图片作为主视觉，完整展示，不裁剪。
- 数据：当前使用原型数据，字段和后续接口契约保持同一颗粒度；原型结局标题只引用真实结局库中的标题，不新增假结局名。
- 本地预览默认使用空态，不请求生产监测 API；只有正式线上域名读取生产聚合数据。

## 页面结构

桌面优先，按 Mac 笔记本 `1710 x 991` 视觉检查；移动端只保证可读折叠。

```text
顶部：标题、游戏名、英文副标题、范围切换
概览：游戏玩家总人数 / 游戏平均停留时间 / 当前玩家通关总次数 / 当前日期
主体左侧：玩家趋势 + 结局图片
主体右侧：玩家排行榜
```

## 核心指标

| UI 文案 | 原型字段 | 后续接口字段 | 真实接入口径 |
|---|---|---|---|
| 游戏玩家总人数 | `players` | `summary.gamePlayerTotal` | 所选范围内有有效游戏 session 或心跳的匿名玩家去重数 |
| 游戏平均停留时间 | `duration` | `summary.averageStayMinutes` | 所选范围内每位匿名玩家有效游戏总分钟数的平均值 |
| 当前玩家通关总次数 | `endings` | `summary.completionTotal` | 所选范围内有效结局提交次数 |
| 当前日期 | `currentDate` | `summary.currentDate` | `Asia/Shanghai` 当前日期，格式 `YYYY.MM.DD` |

顶部指标只展示摘要，不进入复杂运营分析。

停留时间只统计页面可见且游戏进行中的有效 session；页面进入后台或被隐藏时结束当前监测 session，后台挂页时间不计入。

## 玩家趋势

- UI 文案：玩家趋势。
- 接口字段：`activityTrend.points[].siteUserCount`。
- 口径：每个 3 小时窗口内使用过网站的人数；触发过 `site_visit` 或 `game_session_start` 即计入。
- 同一匿名玩家在同一窗口只计 `1` 次。
- 横轴固定：`00 / 03 / 06 / 09 / 12 / 15 / 18 / 21 / 24`。
- 纵轴当前视觉刻度：`0 / 50 / 100 / 500`。

## 玩家排行榜

排行榜字段保持轻量：

- 名次
- 匿名昵称
- 学校 / 院系摘要
- 总分
- 最近人生结局

规则：

- 不展示停留时间列。
- 不展示真实身份。
- 同一匿名玩家在同一范围内只保留最高有效分。
- `today` 没有有效数据时显示 `暂无玩家游戏数据`。

## 时间范围

| 范围 ID | UI 文案 |
|---|---|
| `today` | 今日 |
| `week` | 7 日 |
| `all` | 全部 |

前端按钮只传范围 ID，不把中文文案作为数据键。

## 前端接线边界

当前页面可以继续使用静态数据。后续接真实数据时，只新增数据适配层：

```text
range button
-> fetchDashboard(range)
-> normalizeMonitorDashboard(response)
-> render summary / trend / leaderboard
```

硬规则：

- UI 不直接连接数据库。
- 本地预览默认不请求生产监测 API。
- UI 不重新计算排行榜、平均停留或趋势人数。
- UI 只做格式化、空态和视觉渲染。
- 后端或数据层负责聚合、去重、异常过滤和排名。

## 出界内容

本页面不做：

- 登录、账号、权限后台。
- 玩家详情页。
- 真实身份展示。
- 玩家生命周期、转化漏斗、复杂运营画像。
- 修改现有 `web-app` 主流程。

后续新增监测项时，先更新数据契约，再改接口和 UI。
