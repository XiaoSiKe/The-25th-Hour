# UI 信息架构

最后更新时间：`2026-06-25 +08:00`

## 目的

本文定义当前 UI 的信息层级、主界面区域、入口优先级和移动端布局原则。它只约束展示结构，不定义玩法规则、数值、随机、结算或存档语义。

当前 UI 仍遵守：

```text
GameState
-> toViewModel
-> UI 读取 view model
-> UI 派发 command
-> command 推进 GameState
```

## 玩家决策顺序

主界面应先回答玩家的 4 个问题：

1. 我现在处于哪个阶段。
2. 我当前状态是否危险。
3. 我下一步能做什么，哪些不能做以及为什么。
4. 最近发生了什么，刚才的选择改变了哪些数值。

因此精细 UI 的优先级不是“左中右三栏”，而是：

| 优先级 | 信息 | 主要字段 | 说明 |
|---:|---|---|---|
| 1 | 当前阶段与阻塞状态 | `title`, `subtitle`, `phase`, `interaction`, `pendingInteraction` | 阻塞弹窗存在时，主界面退为背景，先处理弹窗。 |
| 2 | 高危状态与核心资源 | `risk`, `meters`, `money`, `metrics` | 精力、压力、余额、GPA、评图次数必须一眼可见。 |
| 3 | 本周行动与下一步 | `calendar`, `actions` | 行动次数、行动按钮、禁用原因和收益预览是主交互。 |
| 4 | 课题与作品状态 | `calendar.topic`, `courseProgress`, `profile.course`, `profile.mentor` | 课题进度和作品质量不混入顶部 HUD，但要紧邻行动决策。 |
| 5 | 最近反馈 | `logs`, `reviews`, `pendingInteraction.delta` | 最近结算和评图记录解释“为什么状态变了”。 |
| 6 | 角色长期能力 | `profile`, `attributes` | 影响长期路线，但不是每次行动前的第一视线。 |
| 7 | 系统入口 | `systems.entries`, `systems.*` | 高频入口外露，低频入口折叠或放入菜单。 |
| 8 | 音乐与偏好 | `music` + app shell state | 音乐可持续存在，但不抢占行动和弹窗。 |
| 9 | 开发调试 | `seed`, `stateMeta`, `debug` | 只进入开发模式，不默认展示给玩家。 |

## 主界面区域

精细 UI 主界面划分为 6 个区域。区域可响应式重排，但信息归属不变。

| 区域 | 职责 | 数据来源 | 交互边界 |
|---|---|---|---|
| 阶段顶栏 | 显示当前学期、周次、课题、剩余行动、阻塞提示和保存状态。 | `title`, `subtitle`, `calendar`, `interaction`，存档状态来自 app/storage 层。 | 可派发 `save`、打开低频菜单；不直接推进周结算。 |
| 状态仪表带 | 显示精力、压力、余额、GPA、评图次数和高危横幅。 | `meters`, `money`, `metrics`, `risk` | 只展示，不计算风险阈值。 |
| 行动工作台 | 展示本周行动分组、行动按钮、收益预览和不可用原因。 | `actions`, `calendar.actionsRemaining` | 只派发 `perform-action`，不判断行动可用性；`special_skill` 可先打开 app shell 确认层，确认后仍派发 `perform-action`。 |
| 事件与反馈区 | 显示阻塞弹窗、最近日志、最近 delta、评图记录摘要。 | `pendingInteraction`, `logs`, `reviews` | 弹窗选项统一派发 `modal-option`。 |
| 角色课程抽屉 | 展示角色档案、导师、年度课程、属性、课题进度和作品质量。 | `profile`, `attributes`, `courseProgress`, `calendar.topic` | 默认只读；可提供到作品集/路线入口的导航。 |
| 系统与媒体区 | 展示系统入口、主题、音乐、图鉴、商店、作品集等。 | `systems.entries`, `systems.*`, `achievements`, `music` | 系统入口按 `command` 派发；播放器只影响 app shell。 |

## 开场页信息架构

开场页不是营销页，而是进入游戏前的控制台。PNG 参考图中，建筑工作室场景、游戏名和主入口共同构成第一视觉。

| 区域 | 职责 | 数据来源 | 交互边界 |
|---|---|---|---|
| 场景背景 | 建立建筑学院工作室氛围，显示体素角色、模型、图纸和工作台。 | 静态/生成视觉资产。 | 不承载规则信息，不接收游戏 command。 |
| 标题区 | 显示游戏名、英文副标题、版本或构建提示。 | 静态配置、app 版本。 | 不展示内部 seed 或调试阶段。 |
| 主入口卡 | 开始新游戏、继续上次游戏。 | `screen`、storage 读档状态。 | `show-start-form`、`load-save`；无存档或读档失败由 storage/app 状态反馈。 |
| 游戏介绍面板 | 简短说明游戏类型和核心体验。 | 静态文案。 | 只读，不进入规则。 |
| 低频入口预览 | 作者的话、支持作者、公告、社区、排行榜、结局与成就、主题。 | `systems.entries` 中可用于 start 的入口 + 静态配置。 | `ui-dialog`、`toggle-theme`；占位必须显示待开放或链接待填写。 |
| 状态/氛围小组件 | 真实时间、Tip、音乐迷你态。 | app shell、`musicForState(null)`。 | 音乐只影响 app shell，不写入 `GameState`。 |

开场页约束：

- 深浅主题保持同一信息架构，不因为主题切换移动主要入口。
- 开始新游戏是最高优先级，继续上次游戏次之；低频入口不能挤占主入口。
- 排行榜和成就可以在开场页预览，但接口占位或未解锁状态不能伪造真实记录。
- 场景背景复杂时，文本必须放在可读面板上；不要把正文直接压在复杂图纸或模型区域。

## 桌面布局原则

桌面端采用“左侧行动栏 + 中部状态与日志 + 右侧角色课程 + 底部系统与音乐”的高密度控制台结构。顶部状态可以并入中部上方，也可以作为横向仪表带，但信息优先级不能变。

主游戏界面普通周行动已被 `png-references/游戏主要过程的浅色背景页面.png` 和 `png-references/游戏主要过程的深色背景页面.png` 锁定为桌面端强制母版。后续信息架构、组件实现和补图不得把主流程页改成另一种布局。允许的变化只限于真实数据换行、内部滚动、响应式适配、可访问性和对比度修正。

```text
┌───────────────┬────────────────────────────────┬─────────────────┐
│ 品牌/阶段摘要  │ 状态仪表带                       │ 角色属性摘要       │
│ 行动工作台     ├────────────────────────────────┤ 课程/导师/路线入口  │
│ - 本周行动     │ 日志 / 最近变化 / 事件反馈         │ 系统辅助面板       │
│ - 禁用原因     │ - 行动日志                        │ - 作品集/万里路    │
│ - 收益预览     │ - 事件日志                        │ - 导师信息         │
│ 音乐迷你态     ├────────────────────────────────┴─────────────────┤
│               │ 系统功能：商店 / 竞赛 / 升学 / 实习 / 排行 / 成就   │
└───────────────┴──────────────────────────────────────────────────┘
```

布局约束：

- 主要可点击控件最小命中面积不低于 `44px * 44px`。
- 行动区必须可容纳 12 个行动入口；空间不足时区域内部滚动，但不能裁掉按钮。
- 阻塞弹窗拥有最高交互优先级，背景行动按钮即使可见也不能被触发。
- app shell 临时确认层不能冒充阻塞弹窗；专属技能确认层若出现，必须让位于 `pendingInteraction` 驱动的规则弹窗。
- 低频系统入口可以折叠，但“保存、商店、主题、重开、图鉴/成就”不能在视觉重构中消失。
- 音乐播放器可作为常驻小条或折叠面板；本地 MP3/LRC 是调试/过渡能力，不作为正式主入口。
- 主流程桌面第一屏必须同时可见：行动入口、核心状态、最近反馈、角色课程摘要、系统入口概览。
- 主流程普通周桌面版必须能逐项对应 PNG 中的左侧行动栏、中部状态与日志、右侧角色课程、底部系统与音乐入口；不能只满足文字信息完整却偏离参考图构图。
- 主流程可以保留背景网格和轻场景纹理，但不能让背景抢过行动和日志。

## 手机端入口原则

手机端不是正式可玩主流程。手机浏览器打开网站时，只提供开场入口和低频信息：

1. 开场标题和建筑工作室竖屏场景。
2. 开始新游戏主按钮，但点击后只显示电脑端提示，不进入建档表单。
3. 作者的话、请作者喝咖啡续命。
4. 玩家排行榜入口。
5. 建院社区、公告、深浅主题。

手机端验收：

- 不出现横向滚动。
- 不依赖 hover 才能发现入口。
- 所有可点入口命中面积不低于 `44px * 44px`。
- 点击开始新游戏或读档进入主流程时，显示固定提示：“同学你好，手机屏幕太小，放不下你的五年！——请移步电脑端，大屏幕才配得上你的建筑梦。”
- 不展示主流程行动区、状态仪表、日志、角色课程和音乐播放器的手机端布局。
- 动效只用于状态过渡；尊重 `prefers-reduced-motion`。

## 高频与低频入口

| 频率 | 入口 | 展示原则 |
|---|---|---|
| 高频 | 本周行动、阻塞弹窗、保存、当前高危提示 | 常驻或第一屏可见。 |
| 中频 | 商店、作品集、评图记录、角色课程、主题 | 主界面有明确入口，可抽屉或面板打开。 |
| 低频 | 公告、作者的话、社区、语言、排行榜、完整图鉴 | 桌面端放入系统菜单；手机端只保留本轮明确允许的作者/支持、社区、公告、排行榜和深浅主题入口。占位入口必须明确写“预留/待开放/链接待填写”。 |
| 调试 | seed、phase、内部 id、最近结构化 delta、弹窗队列 | 只在开发模式或调试面板展示。 |

## 玩家可见与开发可见边界

玩家可见：

- 当前阶段、学期、周次、课题和剩余行动。
- 精力、压力、余额、GPA、评图次数。
- 课题进度、作品质量、导师、课程、角色属性。
- 行动按钮、行动收益预览、禁用原因。
- 高危提示、最近日志、评图记录、系统入口状态。
- 结局、成就、音乐和可用的设置项。

默认不向玩家展示：

- `seed`
- 内部 `phase` ID
- 内部 action/event/route ID
- `rngState`
- `modalQueue` 结构
- `debug.lastDelta` 原始对象
- 存档版本和内部结局 ID

这些字段可以进入开发模式，但玩家侧必须转译成可理解的中文状态和说明。

## 与设计和维护的关系

- `DESIGN.md` 只在本文信息架构上定义视觉 token、密度、颜色、字体和动效，不改变区域职责。
- 后续维护当前 UI 时，每次替换必须保留本文的信息归属、`view-model-contract.md` 的数据来源和 `../shared/ui-command-mapping.md` 的 command 边界。

## 验收

- 玩家进入主界面后能先看到当前阶段、风险、剩余行动和下一步。
- 主流程普通周桌面实现与主流程深浅 PNG 在区域关系、信息密度、层级和入口位置上保持一致。
- 当前 UI 不回到旧三栏布局。
- 玩家信息和开发调试信息分离。
- 高频入口不被低频系统菜单挤掉。
- 手机端只承担开场入口和低频信息浏览，不进入主流程；不出现横向滚动或 hover-only 入口。
- UI 不新增第二套规则源。
