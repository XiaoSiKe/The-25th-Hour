# 精细 UI 页面 PNG 生成提示词包

最后更新时间：`2026-06-25 +08:00`

## 已确认规则

- 目标：为精细 UI 开发生成 PNG 设计稿。
- 还原要求：像素级还原。
- 优先平台：桌面优先。
- 桌面画幅：统一 `1920x1080`。
- 移动端画幅：建议 `390x844`。
- 文案：PNG 中的文案是布局占位，不是最终文案。
- 数值：PNG 中的数值只要合理撑开布局，不作为真实规则数值。
- 主题：浅色主题全量生成；深色主题只做核心参考。
- 模板：弹窗族、系统面板族、空状态族允许共用模板。
- 像素级边界：布局、间距、层级、控件尺寸、视觉样式按 PNG 还原；真实数据长度、响应式换行和浏览器字体渲染允许工程适配。
- 主流程普通周锁定：`main-week-action-desktop.png` 不再作为自由发散提示词；后续补图、重绘或开发验收必须强制对齐 `游戏主要过程的浅色背景页面.png` 和 `游戏主要过程的深色背景页面.png`。
- 不重复生成规则：如果一个完整页面已经清楚展示某个小组件的普通状态，不必再为该普通状态单独生成 PNG；只有细节看不清、状态不同或需要独立复用时才补局部图。
- 当前已保留 PNG、已覆盖页面和仍需补图项统一读取 `png-reference-index.md`；用户删除的图片不再作为参考，也不作为缺失项。

## 覆盖状态来源

本文件只维护生成提示词。PNG 覆盖状态、废弃参考和补图是否阻塞开发，分别读取：

- `png-reference-index.md`：当前保留 PNG、已覆盖页面、仍需补图项。
- `development-contract.md`：开发前是否必须补图，以及哪些状态可先按组件清单实现；`fine-ui-implementation-readiness.md` 仅保留旧路径转发。

## 通用基础提示词

生成每张桌面 PNG 时，先使用下面这一段，再追加具体页面提示词。

```text
为网页游戏《第二十五小时》设计一张桌面端精细 UI 页面，画幅 1920x1080，16:9。
产品类型是建筑学生人生模拟器，不是营销页、不是后台管理系统、不是概念海报。
视觉方向：像素体素建筑工作室、工程制图面板、课程档案、学生工作台、蓝图网格、高密度游戏控制台、清楚耐看。
界面应像真实可玩的游戏 UI 截图，玩家可以在这里判断状态、选择行动、处理弹窗、查看反馈。

使用浅色蓝图纸面主题：浅纸面背景、细蓝图网格、深墨色文字、蓝色主操作、黄色警示、红色危险、绿色正向状态。
页面可以使用建筑工作室场景作为背景或局部视觉资产，但关键文字必须落在可读面板上。
面板使用小圆角或直角，薄边线，少量结构阴影；不要大圆角卡片堆叠。
字体使用像素中文字体风格，图标使用像素/体素硬边风格，但排版必须清晰，适合长时间阅读和操作。
文字是布局占位，不要求最终文案准确，但所有信息槽位、按钮槽位、状态槽位必须清楚。

避免：玻璃拟态、模糊光斑、装饰性渐变、营销 hero、普通 SaaS 仪表盘、纯抽象蓝图背景、内部调试字段裸露、只靠颜色表达状态。
必须表现：状态数字、行动按钮、禁用态、禁用原因、收益/损失预览、列表、弹窗层级、系统入口、占位状态、危险操作。
```

深色核心参考图可追加：

```text
同一布局生成深色主题版本：深蓝灰背景、低亮蓝图网格、高对比文字、蓝色主按钮、黄色焦点、红色风险。
保持布局、间距、组件尺寸和信息层级不变，只切换 token 风格。
```

## P0：最需要优先补图或已覆盖的核心页面

P0 是精细 UI 开发最需要的页面。它们覆盖主循环、行动、弹窗、反馈、系统入口和结局。  
其中已经由 `png-reference-index.md` 标记为“已覆盖完整参考”的页面，不再重复生成；只有局部细节不清、状态不同或开发前需要像素级裁切时才补图。未覆盖的 P0 才进入优先补图队列，提示词要尽量完整。

### P0-01 main-week-action-desktop.png：主游戏界面，普通周行动

当前状态：已由 `游戏主要过程的浅色背景页面.png` 和 `游戏主要过程的深色背景页面.png` 覆盖普通态桌面参考。两张图是主游戏界面普通周行动的强制母版。除非需要局部放大，不重复生成；如需补图或重绘，必须沿用这两张 PNG 的区域比例、信息密度、面板语言、图标风格、底部系统入口和音乐播放器关系。

强制对齐要求：

- 不允许把主流程页改成普通后台、SaaS 仪表盘、营销页或抽象蓝图海报。
- 不允许重新安排为与 PNG 明显不同的顶部导航、旧三栏方案或低密度卡片流。
- 允许工程适配真实文案长度、数值长度、换行、内部滚动、触控尺寸、对比度和可访问性。
- PNG 中的示例数值、示例行动名和临时文案仍不能成为真实规则源。

为什么最重要：这是玩家停留时间最长的界面，也是精细 UI 的视觉母版。它会决定顶栏、状态仪表、行动区、日志、角色课程、系统入口和迷你音乐播放器的整体关系。

```text
基于通用基础提示词。
页面名称：主游戏界面，普通周行动。

设计游戏主流程的桌面端核心界面，画幅 1920x1080。
这是玩家在普通周行动阶段看到的默认主界面。
必须严格对齐现有 PNG 参考：浅色版参考 `png-references/游戏主要过程的浅色背景页面.png`，深色版参考 `png-references/游戏主要过程的深色背景页面.png`。
布局、区域比例、面板密度、像素/体素图标语言、底部系统入口、音乐播放器位置和整体控制台气质必须按参考图执行，不要自由改成新的界面方案。

整体结构：
顶部是阶段顶栏，占据全宽或接近全宽。
顶栏显示当前学期、周次、课程主题、剩余行动次数、保存状态、设置/系统菜单入口。
顶栏要像学生工作台的状态条，不要像网站导航栏。

顶栏下方是状态仪表带。
状态仪表至少包含：精力、压力、余额、GPA、评图次数、风险摘要。
GPA 可以显示“未知”占位。
余额显示数值，不要做成进度条。
状态数字要清楚，数字宽度稳定，适合频繁变化。

主操作区域是本周行动工作台。
行动工作台需要完整展示 12 个行动入口，按组别排列，例如学习、创作、生活、兼职。
每个行动按钮包含：行动名称、可用状态、收益预览、消耗或影响摘要。
行动按钮看起来可点击，按钮高度足够，文字能换行。
行动区可以内部滚动，但不能看起来像把行动入口裁掉。

右侧或主区域旁边是事件与反馈区。
包含最近日志、最近一次变化、评图摘要或事件反馈摘要。
最近变化要能解释玩家刚才选择为什么改变了数值。

侧边或底部保留角色与课程信息。
包含角色姓名/昵称、大学、导师、年度课程、当前课题、课程进度、作品质量、属性摘要。
不要展示内部 phase id、rngState、action id、event id。

系统入口区要能看到底端栏：商店购物、竞赛投稿、考研升学、申请保研、考公考编、出国留学、实习与工作、转行、结局与成就。
右侧入口要能看到个人作品集与简历、建筑生的万里路。
低频入口包含排行榜、公告、主题、保存、重新开始等入口的组织方式。
低频入口可以折叠或收进系统菜单，但必须看得出有入口。

迷你音乐播放器可以出现在侧边栏底部或主界面底部。
播放器普通状态包含曲名、播放/暂停、进度或时间；下一首按钮需要展示可用/禁用状态，只有购买 `音乐会员` 后才对当前学年 BGM 可用，结束曲状态不可用。
如果这张图中播放器足够清楚，就不需要再单独生成迷你播放器普通状态图。

视觉要求：
高密度但清楚。
不要照搬旧三栏感。
信息优先级是：当前阶段、风险与资源、本周行动、最近反馈、角色课程、系统入口、音乐。
```

### P0-02 main-risk-desktop.png：主游戏界面，高危状态

为什么最重要：风险状态决定玩家是否能理解失败压力、资源危险和行动限制。这里必须从设计稿阶段就锁定表达方式。

```text
基于通用基础提示词。
页面名称：主游戏界面，高危状态。

设计同一个主游戏界面的高危版本，画幅 1920x1080。
布局与普通周行动主界面保持一致，方便开发做状态切换。

必须展示至少一种高危：
压力过高，或精力过低，或余额不足。
建议同时展示两个风险槽位，例如压力高危、余额紧张。

顶部或行动区上方要有明显高危横幅。
横幅包含：风险等级、风险原因、可能影响、建议下一步。
风险提示不能只靠红色，必须有文字解释。

状态仪表中的相关指标要进入警示状态。
例如压力数字高亮并配合“高压”标签；余额数字配合“余额不足风险”说明。

行动区仍然可见。
部分行动按钮变为禁用状态，并在按钮内或按钮下方显示原因，例如精力不足、余额不足、当前阶段不可用。

右侧反馈区显示最近导致风险升高的日志或变化摘要。
玩家应该能从画面看懂“我为什么危险”和“下一步能怎么办”。
```

### P0-03 action-workbench-detail-desktop.png：行动工作台细节

为什么最重要：行动按钮是游戏最主要交互。像素级开发需要清楚知道按钮、组别、禁用原因和收益预览怎么摆。

```text
基于通用基础提示词。
页面名称：行动工作台细节。

设计主界面中行动工作台的局部放大参考图，画幅 1920x1080。
可以让行动区占据画面主要空间，周围保留少量顶栏和状态仪表作为上下文。

行动工作台必须展示 12 个行动入口。
行动按组别组织，例如：
学习类：学习 AI 软件、阅读展览、场地调研。
创作类：设计迭代、普通画图、爆肝画图。
生活类：运动、社交、休息。
收入类：外包、兼职。
特殊类：特殊技能。

每个行动按钮包含：
行动名称。
可用/禁用状态。
收益预览，例如 +作品进度、+软件、-精力、+压力、+余额。
如果是禁用，显示禁用原因。
如果是外包/兼职，显示“进入项目选择后结算”的语义。

同一张图中必须同时出现：
可用行动。
禁用行动。
带收益预览的行动。
带不可用原因的行动。
可检查门槛或进入二级选择的行动。

禁用原因不能只放 tooltip。
禁用文字要在按钮内部或紧贴按钮下方直接可见。

行动区可以有内部滚动边界，但当前截图里要能看出行动入口不会被裁掉。
按钮触控目标要足够，文字允许换行。
```

### P0-04 modal-event-choice-desktop.png：阻塞事件选择弹窗

当前状态：基础骨架已由 `随机事件的界面.png` 覆盖。后续只在需要多选项、禁用选项或长正文时补图。

为什么最重要：所有固定事件、随机事件、导师/课程选择都依赖统一弹窗规则。先锁一个高质量弹窗模板，后续弹窗才能共用。

```text
基于通用基础提示词。
页面名称：阻塞事件选择弹窗。

设计一个覆盖主界面的阻塞弹窗，画幅 1920x1080。
背景是游戏主界面，但被遮罩处理，背景不可操作。
前景是事件选择弹窗。

弹窗内容：
顶部有事件类型标签、标题、当前阶段/周次辅助信息。
中间是事件正文，适合 2-4 段短文本。
底部是 2-4 个选项按钮。

每个选项按钮包含：
选项名称。
一行后果或收益预览。
可能的数值变化槽位。
如果某个选项不可用，按钮禁用并显示原因。

按钮文案必须有具体语义，不要统一写“确定”。
弹窗底部可以有小型说明，例如“选择后进入结果反馈”。

视觉要求：
弹窗层级强，遮罩明确。
背景行动按钮即使可见，也明显不可点击。
弹窗内文字可读，按钮高度足够。
```

### P0-05 modal-result-desktop.png：选择结果与数值变化弹窗

为什么最重要：玩家需要理解行动/事件后的反馈。结果弹窗决定 delta、日志和下一步语义的展示方式。

```text
基于通用基础提示词。
页面名称：选择结果与数值变化弹窗。

设计玩家做出选择后的结果弹窗，画幅 1920x1080。
背景主界面被遮罩，前景弹窗展示结果。

弹窗内容：
顶部显示结果标题，标题可以引用玩家刚才选择的选项语义。
正文描述发生了什么。
中部展示数值变化列表，也可以叫 delta 摘要。

delta 摘要同时包含正向和负向变化，例如：
精力 -8。
压力 +6。
作品进度 +12。
余额 +300。
属性小幅提升。

正向和负向变化必须同时用符号、文字和颜色表达，不只靠颜色。

底部主按钮展示下一步语义，例如“回到本周行动”“进入评图结果”“继续下一事件”。
不要只写“确定”。

如果有日志摘要，要在弹窗内或背景反馈区展示一条即将写入日志的摘要槽位。
```

### P0-06 system-menu-desktop.png：系统入口菜单

为什么最重要：系统入口数量多、状态复杂，必须先确认可用、占位、危险操作如何区分。

```text
基于通用基础提示词。
页面名称：系统入口菜单。

设计游戏内系统入口菜单，画幅 1920x1080。
可以是右侧抽屉、全屏面板或主界面内的大菜单，但必须像游戏内工具菜单，不像网站导航。

入口分组：
高频：保存、设置、主题、商店购物。
中频：个人作品集与简历、竞赛投稿、实习与工作、建筑生的万里路、结局与成就。
底端未来方向：考研升学、申请保研、考公考编、出国留学、转行。
低频：排行榜、公告、作者的话、支持作者、社区、语言。
危险操作：放弃当前学业/重新开始。

每个入口至少包含：
入口名称。
当前状态标签，例如可用、最小版、占位、待开放、静态说明。
一行说明或禁用原因。
可点击按钮或禁用按钮。

占位入口必须明确显示“预留”“待开放”“链接待填写”等语义。
危险操作必须远离主操作，并使用明确危险样式。
不要让占位入口看起来像完整功能。
```

```text
当前余额。
商店状态说明。
关闭或返回按钮。

商品名称。
```

### P0-08 ending-page-desktop.png：结局页

```text
基于通用基础提示词。
页面名称：结局页。

设计游戏结局页面，画幅 1920x1080。
这是玩家达成毕业结局或失败结局后看到的页面。

页面主体：
结局标题。
结局正文。
结局类型标签，例如毕业、失败、成长结局等。

最终精力、压力、余额、GPA、评图次数、作品集或成就分。

记录区：
最近关键记录。
本局解锁成就。
图鉴入口。

操作区：
重新开始。
查看成就/结局图鉴。
主题切换。

音乐区：
结束曲播放器。
曲名、播放/暂停、进度、歌词或歌词入口。

视觉要求：
有结局仪式感，但仍然是游戏结果页，不是海报。
```

## P1：重要但可以第二批生成

P1 页面建议生成，但不必早于 P0。它们常常可以从 P0 模板推导。

### P1-01 start-menu-desktop.png：开始界面

次要原因：开始流程已有首批精细 UI 基线，不是当前最大风险。但像素级还原最终仍需要。

```text
基于通用基础提示词。
页面名称：开始界面。
设计桌面端开始菜单。
左侧是游戏标题、英文副标题、简介、主题状态、真实时间。
右侧是开始新游戏、继续上次游戏、公告、作者的话、支持、主题、社区、排行榜、成就、语言等入口。
```


## P2：低频或可用模板推导的页面

P2 可以后补。它们不建议阻塞第一批精细 UI 开发。

### P2 系统面板族

这些页面建议共用系统面板模板。生成时只需要在 P0/P1 模板稳定后，按内容替换。

- `competition-panel-desktop.png`：竞赛投稿面板，展示投稿建议和后续版本说明，不伪造获奖结果。
- `internship-work-panel-desktop.png`：实习与工作面板，展示软件、设计、汇报能力、实习建议和建筑工作入口，不伪造 offer。
- `portfolio-resume-panel-desktop.png`：个人作品集与简历面板，展示作品集分、评图入库和简历素材。
- `wanli-road-panel-desktop.png`：建筑生的万里路面板，展示开放条件、当前地点和地点事件入口。
- `postgrad-exam-panel-desktop.png`：考研升学面板，展示开放条件、候选方向和考试入口，不泄露内部成功率。
- `recommendation-panel-desktop.png`：申请保研面板，展示开放条件、候选方向和复试入口，不泄露内部成功率。
- `public-service-panel-desktop.png`：考公考编面板，展示选调、考公、考编子方向和考试入口，不泄露内部成功率。
- `overseas-study-panel-desktop.png`：出国留学面板，展示开放条件、候选院校和语言考试入口，不泄露内部成功率。
- `career-change-panel-desktop.png`：转行面板，展示开放条件、候选岗位和投递入口，不泄露内部成功率。
- `leaderboard-panel-desktop.png`：排行榜面板，展示真实榜单、空榜或接口失败降级、我的本地毕业档案槽位，不造假数据；如需 Top 100，先同步接口上限和 UI 容器。
- `announcement-panel-desktop.png`：公告面板，展示版本说明和关闭按钮。
- `author-panel-desktop.png`：作者的话，长文本阅读区和关闭按钮。
- `coffee-support-panel-desktop.png`：支持作者，二维码/链接/鸣谢占位。
- `community-panel-desktop.png`：社区入口，群、投稿、故事墙占位。
- `language-panel-desktop.png`：语言面板，当前中文可用，其他语言待开放。
- `guide-panel-desktop.png`：游戏指南，说明核心循环。

通用提示词：

```text
基于通用基础提示词。
页面名称：替换为具体系统面板名称。
设计一个游戏内系统面板。
使用与系统入口菜单一致的视觉骨架。
包含标题、状态标签、内容摘要、空状态或占位说明、返回/关闭按钮。
如果系统未接入，必须明确显示“预留/待开放/链接待填写/接口未接入”。
不要伪造真实数据、排行、录取、获奖或结局记录。
```

## 不需要单独生成的情况

如果 P0 主界面已经清楚展示以下普通状态，可以不单独生成：

- 迷你音乐播放器普通状态。
- 状态仪表普通状态。
- 角色课程摘要普通状态。
- 系统入口普通按钮状态。
- 最近日志普通列表状态。

需要单独补图的情况：

- 主界面里太小，无法看清像素级细节。
- 该组件有展开态、错误态、禁用态或资源缺失态。
- 组件会跨多个页面复用，但不同页面截图表现不一致。
- 开发需要独立裁切参考。
