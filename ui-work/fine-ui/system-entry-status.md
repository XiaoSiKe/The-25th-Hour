# 系统入口状态表

最后更新时间：`2026-06-28 +08:00`

## 目的

本文确定当前 UI 必须保留的系统入口、首发状态、占位文案要求和最小验收标准。系统入口状态只服务 UI 展示、排期和验收，不参与 `GameState` 规则判断。

状态定义：

| 状态 | 含义 |
|---|---|
| 必须完成 | 当前可玩闭环必须可用，不能只留按钮。 |
| 首发必须完成 | 首发上线必须完成；当前实现阶段可保留占位入口，但不能漏掉，也不能伪装成已接入。 |
| 最小版完成 | 首版只做信息汇总或只读说明，不做完整长期系统。 |
| 静态完成 | 展示静态页面、静态弹窗或配置外链状态，不进入游戏规则状态。 |
| 可占位 | 允许保留入口和预留说明，不能伪装成完整功能。 |
| 后置 | 当前不进入首发实现；若入口出现，必须标注为规划中。 |

说明：`最小版完成` 只描述系统面板的首批展示颗粒度，不覆盖 `PRD.md / systems.md / numbers.md` 中已经确定的玩法规则。竞赛投稿、实习与工作和五个未来方向入口若已有或后续接入真实规则，只能通过 VM 与 command 展示和推进，不能由 UI 面板自行模拟结算。

时间口径：

- “当前可占位”只适用于未到首发上线前的当前实现阶段。
- “首发必须完成”表示正式首发上线前必须接入真实数据或明确降级策略；占位文案不能作为首发完成标准。
- 排行榜这类外部接口入口可以先保留按钮和占位说明，但不得展示假榜单、假排名或假总分。

## 占位入口文案规则

可占位入口必须满足：

- 按钮、弹窗或页面明确写出“预留”“待开放”“链接待填写”之一。
- 不展示虚假的列表、假排名、假投稿结果或假语言切换结果。
- 不写入 `GameState`，不产生日志，不触发成就，除非该行为已由命令层和成就规则明确支持。
- 外链未配置时不可跳转；已配置时用新标签页打开，并使用 `noopener,noreferrer`。
- 占位入口可关闭，可返回游戏，不阻塞主流程。

## 必须完成入口的最小验收

| 入口 | 最小验收 |
|---|---|
| 开始新游戏 | 表单必填；创建后出现 1 张角色卡，可免费重抽 2 次；创建日志写入。 |
| 继续上次游戏 | 读取成功后恢复到合法阶段；读取失败不清空当前内存状态。 |
| 保存 | 保存成功可再次读回；保存失败有反馈；正式版不继续扩展整局 localStorage。 |
| 商店购物 | 金钱不足、限购、当前阶段不可买、弹窗阻塞时都有原因；购买后走命令层并弹出结算。 |

| 放弃学业重新开始 | 游戏内首次点击先确认；确认后清空当前局状态，只删除当下该局的本地存档，不删除之前的存档，重置音乐状态并回到游戏开始页；当下该局所有记录不写入跨局记录。 |

## 与 View Model 的对应

`web-app/game/view-model.mjs` 已提供 `systems.entries`，用于精细 UI 渲染系统入口菜单：

```text
systems.entries[]
  id
  label
  launchStatus
  statusLabel
  command
  surface
  copyRequirement
  availability.state
  availability.reason
```

后续精细 UI 替换系统菜单时，应优先读取 `systems.entries`，而不是在组件里重新维护一份入口状态表。本文只作为验收源；入口 ID、标题、状态标签、命令和运行时可用性以 `web-app/game/view-model.mjs` 中的 `SYSTEM_ENTRY_DEFINITIONS` 与 `systemEntryAvailability` 为准。

## 验收

- 精细 UI 不会把可占位入口做成完整功能。
- 首发必须入口不会被视觉重构时漏掉；若接口失败、空榜或降级，必须明确标注状态并保留首发前完成要求。
- 商店购物、保存、主题、排行榜、结局与成就这些高优先级入口都有可验收的最小行为。
- 系统入口状态与规则推进分离，不新增第二套规则源。
