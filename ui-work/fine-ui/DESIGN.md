# 当前前端页面 UI 设计规范

最后更新时间：`2026-06-25 +08:00`

## 目的

本文是当前游戏前端页面 UI 的视觉和交互来源。它只定义表现层规则，不定义玩法、数值、事件、路线、结算或存档语义。

当前 UI 必须继续遵守：

```text
GameState
-> toViewModel
-> UI 只读 view model
-> UI 派发 command
-> command 推进 GameState
```

## 当前实现 Module

真实玩家页面读取以下 Module：

| Module | 职责 |
|---|---|
| `../../web-app/index.html` | 固定 `1710 x 991` 舞台比例，缩放并承载 `game.html`。 |
| `../../web-app/game.html` | 真实游戏 UI 挂载页。 |
| `../../web-app/stage.mjs` | 舞台缩放、居中和窗口变化同步。 |
| `../../web-app/app.mjs` | app shell 状态、事件委派、存档过渡、音乐播放、截图和 UI 弹窗调度。 |
| `../../web-app/ui/render.mjs` | 从 view model 渲染开场、主流程、弹窗、系统入口和结局页面。 |
| `../../web-app/styles.css` | 当前视觉 token、布局、主题、动效和响应式规则。 |
| `../../web-app/ui/icons.mjs` | UI 图标路径、主题图标和像素图标渲染。 |

`../../web-app/game/*` 是规则和 view model 来源。UI 不直接修改 `GameState`，不复制规则判断，不新增第二套行动、事件、路线或结局逻辑。

## 视觉方向

产品是可长时间游玩的网页游戏，不是营销页。界面应优先服务状态判断、行动选择和阻塞流程处理。

PNG 参考图已把最终方向收束为“像素体素建筑工作室 + 工程制图面板 + 高密度游戏控制台”。蓝图网格仍是基础纹理和结构语言，但不能把界面做成纯抽象蓝图仪表盘。开场页和关键页面必须让玩家第一眼感到这是建筑学院工作室里的模拟器，而不是普通 SaaS 工具。

关键词：

- 建筑制图
- 课程档案
- 学生工作台
- 蓝图网格
- 高密度信息
- 清楚耐看
- 像素体素建筑工作室
- 工程面板
- 游戏控制台

PNG 对齐原则：

- 开场页：真实感体素建筑工作室场景是第一视觉信号，UI 面板覆盖其上，但不能把场景完全遮死。
- 主流程页：以高密度控制台为母版，左侧行动、中部状态与日志、右侧角色课程、底部系统入口和音乐播放器共同构成游戏工作台。
- 弹窗：使用强遮罩、像素警示或类型图标、明确标题、正文、delta 摘要和下一步语义。
- 视觉资产：角色、图标、模型、图纸和工作室道具应保持像素/体素语言；普通扁平图标只能作为临时占位。
- 深浅主题：共享信息架构和组件尺寸，只切换场景氛围、面板 token、网格亮度和文字对比。

## PNG 强制对齐

主游戏界面普通周行动是当前精细 UI 的锁定母版。桌面浅色版必须对齐 `png-references/游戏主要过程的浅色背景页面.png`，桌面深色版必须对齐 `png-references/游戏主要过程的深色背景页面.png`。

开发时必须按这两张 PNG 保持：

- 左侧行动栏、中部状态与日志、右侧角色课程、底部系统入口和音乐播放器的区域关系。
- 顶栏、状态仪表、行动按钮、日志、角色课程摘要、系统入口的相对层级和信息密度。
- 工程面板、小圆角或直角、薄边线、像素/体素图标、蓝图网格和建筑工作室场景的视觉语言。
- 深浅主题的同构结构：同一区域职责、入口位置、命中面积和信息顺序不因主题切换改变。

允许的工程适配只包括：真实数据长度、文案换行、区域内部滚动、窄桌面响应式折叠、对比度修正、键盘焦点、手机入口页触控尺寸和浏览器字体渲染差异。除此以外，任何偏离 PNG 的主流程布局、低密度留白、普通 SaaS 仪表盘化、营销 hero 化、抽象蓝图海报化，都视为不通过验收。

如果本文文字和 PNG 在布局、密度、层级或视觉语言上冲突，以 PNG 为准，并先更新对应 Markdown 后再进入实现。

避免：

- 大面积玻璃拟态和无意义模糊。
- 装饰性渐变、漂浮光斑和过度拟物。
- 大圆角卡片堆叠。
- 把内部 ID、seed、phase 当作正式玩家信息。
- 用颜色作为唯一状态表达。
- 纯抽象蓝图背景替代建筑工作室场景。
- 普通后台/管理台/SaaS 仪表盘气质。
- 营销 hero 式开场页。
- 与 PNG 不一致的大面积低密度留白。

## 色彩 Token

CSS 以语义 token 为准。组件不得临时发明新的主色。

| Token | 用途 |
|---|---|
| `--surface-bg` | 页面背景。 |
| `--surface-grid` | 细网格线。 |
| `--surface-grid-strong` | 结构网格线和投影边。 |
| `--surface-panel` | 主要面板。 |
| `--surface-panel-soft` | 次级面板、输入和 hover 底。 |
| `--text-main` | 主要文本。 |
| `--text-muted` | 次级文本。 |
| `--text-faint` | 辅助文本。 |
| `--line-subtle` | 常规边线。 |
| `--line-strong` | 弹窗、重点面板和分隔。 |
| `--accent-primary` | 主操作、关键进度。 |
| `--accent-primary-strong` | 主按钮和重点数字。 |
| `--accent-success` | 正向状态。 |
| `--accent-warning` | 警示、焦点和高亮。 |
| `--accent-danger` | 高危、错误、危险操作。 |
| `--focus-ring` | 键盘焦点。 |

浅色主题以纸面、蓝图线、墨色文字和日光工作室场景为主；深色主题以夜间工作室、深蓝灰底、低亮网格和高对比文本为主。深浅色必须同时检查对比度，不能只反转颜色。

主题关系：

- 浅色主题：面板接近半透明白纸/描图纸，但文本区域必须有足够实底，避免场景干扰阅读。
- 浅色主题的主流程细节要保留纸面感但提高结构边界：日志面板允许使用轻微白灰底，当前浅色日志面板灰度以 `33%` 轻灰混合为准；精力、压力、进度、质量和个人属性等状态进度条应使用偏灰的深色填充，不使用纯黑压住页面；音乐播放器进度条可以比普通状态进度条略黑；阻塞弹窗和玩家主动打开的系统弹窗最外框使用更明显的 7px 墨色边框，弹窗内关键信息框也要有略粗的墨色边框。
- 浅色主题下，常规阻塞弹窗、玩家手动点开的系统入口页和按钮进入的常规页面，主背景不得使用纯白，应使用约 `42%` 轻灰混合的纸面底色；有专门仪式感或深色流程背景的固定流程卡可保留其独立背景。
- 浅色主题的警告框使用更浅、更透明的红色底，只保留明确红色语义，不做深红实底；警告文案必须仍可读。
- 浅色主题中，个人简历里的作品集卡片可使用轻微蓝紫渐变，但蓝紫强度要比原视觉减弱约 `10%`；“查看个人作品集”按钮内部保持白色纸面，不使用蓝色渐变，hover 时加重边框、阴影和底部压线。
- 浅色主题中，出国留学里的雅思报考入口使用带蓝感的浅色按钮，不做黑底按钮；竞赛投稿目录卡片参照考研升学候选卡的白灰纸面 UI，使用黑色文字和灰墨边线，不出现蓝色渐变感。
- 结尾动画播放完后的“同学毕业快乐”按钮和可见的“跳过结尾回忆动画”按钮在浅色主题中沿用深色按钮语气，保持结尾仪式感。
- 深色主题：面板接近压暗玻璃钢板/工程仪器面板，但不做模糊玻璃拟态；边线和重点状态可以有轻微发光。
- 场景背景：开场页可以露出更多背景；主流程页以 UI 工作台为主，背景纹理必须退后。
- 同一页面的深浅版本必须保持区域职责、入口位置、命中面积和信息顺序一致。

## 字体层级

默认字体继续使用像素中文字体栈，但排版按信息密度控制：

| 层级 | 建议 |
|---|---|
| 页面标题 | 2rem 到 3rem，仅用于开始页、结局页和角色选择页。 |
| 面板标题 | 1rem 到 1.35rem，保持紧凑。 |
| 正文 | 14px 到 16px，移动端不低于 14px。 |
| 标签和状态 | 0.78rem 到 0.86rem，可用全大写英文作为辅助。 |
| 数字 | 使用 tabular numbers，避免状态仪表跳动。 |

不使用负 letter spacing；长文本优先换行，不挤压按钮。

## 间距和布局密度

基础间距采用 4px / 8px 节奏：

| Token | 建议值 | 用途 |
|---|---:|---|
| `--space-1` | 4px | 紧密标签。 |
| `--space-2` | 8px | 按钮内距、列表间距。 |
| `--space-3` | 12px | 面板内距。 |
| `--space-4` | 16px | 区块间距。 |
| `--space-5` | 24px | 页面边距、弹窗内距。 |
| `--space-6` | 32px | 大屏 hero 内距。 |

桌面主界面保留多区域并列，当前采用“左侧行动栏 + 中部状态与日志 + 右侧角色课程 + 底部系统入口和音乐”的高密度控制台结构。手机端不承载正式主流程，只提供开场入口、介绍、排行榜/成就、作者/支持、社区、公告和深浅主题；尝试开始或读档进入游戏时提示移步电脑端。

## 组件样式原则

| 组件 | 原则 |
|---|---|
| 面板 | 小圆角或直角，薄边线，少量结构投影；不嵌套装饰卡片。 |
| 按钮 | 触控目标至少 44px，高频主按钮有明确主色；危险操作使用 danger 样式。 |
| 系统入口 | 读取 `vm.systems.entries`；展示状态标签、占位/禁用原因，不维护第二份入口清单。 |
| 状态仪表 | 文字、数值、进度条并存；压力和余额风险不能只靠颜色表达。 |
| 列表 | 分隔线轻、行高稳定、长文本可换行。 |
| 弹窗 | 有强 scrim、明确标题、阻塞流程时背景不可继续行动；选项禁用原因靠近按钮。 |
| 表单 | 可见 label、必填字段、输入高度接近触控目标；错误提示在字段附近。 |
| 音乐播放器 | 正式曲目为主；本地 MP3 / LRC 是测试入口，需弱化。 |

## 像素资产与图标

PNG 参考图使用像素体素角色、像素工具图标和建筑工作室道具作为识别系统。当前 UI 文档和后续开发应遵守：

- 行动、系统入口、状态仪表优先使用像素图标或与像素图标一致的硬边风格。
- 图标必须帮助识别入口，不做纯装饰重复。
- 角色头像、导师头像、成就图标和系统入口图标可以复用像素图标骨架，但状态标签和禁用原因仍要用文字说明。
- 已确认图标的开发入口为 `../../asset-work/ui-icon-final/README.md`；补图和新增图标才回到 `../../asset-work/prompts/ui-icon-page-inventory.md`。
- 场景图只服务氛围和品牌识别，不承载规则信息；关键文字不得压在复杂场景上直接阅读。
- 手机端开场页使用正式竖屏壁纸资产 `../../web-app/assets/start/start-scene-mobile-light.png` 与 `../../web-app/assets/start/start-scene-mobile-dark.png`；它们只服务开场入口氛围，不作为主流程手机布局参考。
- 任何外部或生成资产进入开发前，都要记录用途、来源和替代方案，避免后续因为资产缺失阻塞 UI。

## 页面母版

| 页面 | 母版方向 | 关键约束 |
|---|---|---|
| 开场页 | 场景背景 + 左侧大标题和入口控制台 + 中部说明面板 + 低频系统预览。 | 第一屏必须出现游戏名和建筑工作室场景；不是营销落地页。 |
| 主流程页 | 高密度游戏工作台，左行动、中状态日志、右角色课程、底部系统入口。 | 必须强制对齐主流程深浅 PNG；行动、状态、日志、角色课程摘要不能从桌面第一屏消失。 |
| 阻塞弹窗 | 遮罩后的主流程背景 + 居中工程弹窗。 | 背景不可操作；delta 摘要和下一步按钮语义清楚。 |
| 系统面板 | 游戏内工具菜单或抽屉。 | 可用、最小版、占位、静态、危险操作必须视觉区分。 |
| 结局页 | 对应人生结局插画 + 结果正文 + 状态摘要 + 成就/图鉴 + 结束曲。 | 插画读取 `asset-work/assets/images/ending-illustrations/` 的映射资产；有仪式感但仍是游戏结果页，不做纯海报。 |

## 状态色

- 正向变化：`--accent-success`，并配合 `+` 文本。
- 负向变化：`--accent-danger`，并配合原因或 `-` 文本。
- 压力增加：按负向处理；压力减少按正向处理。
- 占位入口：使用 muted 文本和虚线/轻边框，不伪装成完整功能。
- 禁用态：使用 `disabled` 属性、降低透明度、禁用 cursor，并保留原因。

## 动效

动效只表达状态变化，不做纯装饰：

- hover / press / focus：150ms 到 180ms。
- 进度条变化：180ms 到 220ms。
- 字幕和弹窗内容进入：200ms 到 260ms。
- 只动画 `opacity`、`transform` 或颜色，不动画布局尺寸。
- 尊重 `prefers-reduced-motion: reduce`。

## 维护基线

后续任何 UI 整理、拆分或修复都必须检查：

- command 没变。
- view model 数据来源没变。
- 阻塞流程没变。
- 禁用态和原因仍可见。
- 占位入口仍明确告知玩家。
- UI 没有新增规则判断。
- 主流程普通周截图能和对应 PNG 在布局、密度、层级和视觉语言上逐项对齐。

旧粗 UI 交接文件和独立预览脚手架已经删除。若需要新的检查工具，优先服务当前真实页面链路，避免重新建立与主入口平行的 UI 实现。
