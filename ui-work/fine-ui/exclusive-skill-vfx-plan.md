# 专属技能确认 UI 与数值反馈方案

最后更新时间：`2026-06-25 +08:00`

## 目的

本文定义专属技能点击后的确认界面和数值反馈方案。它只描述表现层，不改变玩法、数值、冷却、行动次数、事件、存档或结算规则。

需求约束：

- 玩家点击行动区的专属技能按钮后，先打开一个 app shell 专属技能确认 UI。
- 技能 UI 的标题统一使用当前角色的技能名。
- 技能 UI 底部只有一个主要确认按钮，按钮文案按角色区分。
- 玩家点击技能 UI 底部按钮后，才执行技能并开始数值反馈动效。
- 特效不做复杂粒子雨、烟花、爆炸或大面积全屏动画。
- 特效重点体现在相关数值和进度条的动态变化，让玩家清楚感到技能生效。

## 设计原则

专属技能不是普通行动的直接点击反馈，而是一次角色化的“确认释放”。第一下点击让玩家进入技能语境，第二下点击才真正结算。

视觉方向继续沿用精细 UI 的母版语言：

- 建筑制图
- 像素/体素工作室
- 蓝图网格
- 工程面板
- 高密度游戏控制台

避免：

- 点击行动按钮后立刻结算技能。
- 用粒子雨、金币雨、烟花、强闪白或强震动表达技能。
- 让特效遮挡日志、弹窗按钮或核心状态超过一瞬。
- 通过特效表达新的隐藏规则。
- 在 UI 层重新判断冷却、压力、金钱或行动次数。

## 交互流程

```text
点击行动区“专属技能”
-> 如果该行动可用，打开 app shell 专属技能确认 UI
-> 不消耗行动次数，不进入冷却，不写日志，不写 GameState.pendingInteraction
-> 玩家点击确认 UI 底部按钮
-> 执行 performAction(state, "special_skill")
-> result.ok 后关闭确认 UI
-> render 更新状态
-> 相关数值和进度条播放变化动效
-> advanceGameFlow / save 照旧
```

如果玩家关闭确认 UI 或按 `Esc` 返回，不执行技能，也不播放数值动效。

如果确认时命令失败，例如状态已经变化导致技能不可用，不播放数值动效，并显示命令层返回的原因。

## 接入边界

专属技能按钮当前是统一行动：

```text
action.id = "special_skill"
```

角色差异运行时来自 view model 中的当前角色展示字段，并由角色配置映射补足技能文案：

```text
profile.characterId
profile.characterName
profile.skillName
profile.skillText
profile.skill
```

建议保持这个边界：

- `action.id="special_skill"` 是行动按钮的两段式交互特例；其他行动仍按通用行动按钮直接派发 `perform-action`。
- 第一次点击专属技能按钮只打开 app shell 确认 UI，不派发游戏 command。
- 确认 UI 只展示当前角色技能信息和确认按钮。
- 真正执行仍走命令层 `performAction(state, "special_skill")`。
- 数值动效只读取命令执行前后的可见状态差异。
- UI 层不复制任何可用性规则；专属技能是否可用、冷却、消耗和门槛仍以 `vm.actions[]` 与命令层返回为准。
- 确认 UI 的打开、关闭和取消属于 app shell 临时状态，不进入 `GameState`、不进入 `pendingInteraction`、不走 `modal-option` 路由。

## 确认 UI

确认 UI 是 app shell 的临时确认遮罩，交互上会暂时占用焦点，但它不是规则阻塞流程。文档中提到的“阻塞流程”“阻塞弹窗”仍只指 `GameState.pendingInteraction` 驱动的规则弹窗。

确认 UI 不写入 `GameState.pendingInteraction`，不改变 `interaction.isBlocking`，不进入 `modal-option` 路由。刷新页面或关闭确认 UI 后，应回到主流程，不留下半执行状态。

如果当前已经存在 `pendingInteraction`，专属技能确认 UI 不应打开；玩家必须先处理规则阻塞弹窗。若确认期间命令层状态变化导致 `special_skill` 不可用，确认按钮执行后只显示命令层返回原因，不播放数值动效。

推荐结构：

| 区域 | 内容 |
|---|---|
| 顶部 | 技能名，读取 `profile.skillName` 或同等 VM 展示字段。 |
| 中部 | 角色名、技能效果摘要、将变化的状态预览。 |
| 底部 | 单个主要按钮，文案按角色读取。 |
| 右上 | 关闭图标按钮，可取消释放。 |

标题示例：

```text
放平心态
```

底部按钮示例：

```text
别紧张，放松
```

确认 UI 不需要解释“点击后释放技能”这类说明文字。按钮文案本身负责表达角色语气。

## 数值反馈动效

确认按钮点击成功后，特效只体现在相关数值和进度条上。

推荐反馈节奏：

| 阶段 | 时间 | 表现 |
|---|---:|---|
| 锁定变化对象 | `0ms` 到 `80ms` | 只有本次会变化的数值条亮起 1 次，未变化的仪表保持静止。 |
| 旧值留影 | `80ms` 到 `160ms` | 条形轨道保留一条淡色旧值刻度，让玩家能看出变化从哪里开始。 |
| 条形缓动 | `160ms` 到 `1100ms` | 条形从旧值缓慢移动到新值，变化区段出现清晰可见的蓝色或红色动态覆盖层，填充条本体保持原有状态色。 |
| 结果落点 | `1100ms` 到 `1280ms` | 旧值刻度、变化色段和扫光淡出，最终条形回到常态。 |

推荐反馈组件：

| 类型 | 表现 |
|---|---|
| 旧值刻度 | 用一条 1px 淡线标出旧值位置，帮助玩家看出增加或回退。 |
| 条形过渡 | 条形填充从旧值移动到新值，正向变化向右推进，负向变化向左回退。 |
| 变化区段 | 只在旧值和新值之间显示动态色段；正向/收益为清晰蓝色，负向/代价为更明显的红色；加载完成后不保留蓝/红。 |
| 轨道淡扫光 | 变化条内部出现一次低透明度扫光，作为“技能正在生效”的轻微特效。 |
| 状态轻亮 | 变化期间受影响条形和所在状态块轻微提亮，不做缩放、不做强光晕。 |
| 蓝红语义 | 精力、进度、质量、金钱、GPA 增加为蓝色；这些数值降低为红色。压力下降为蓝色，压力上升为红色。 |
| 金钱数字 | 涉及金钱收支时不播放进度条或临时条，只在金钱状态块上显示 `+¥` / `-¥` 的数字变化动效。 |
| GPA 数字 | 涉及个人 GPA 或 GPA 修正时不播放进度条，也不显示浮动变化量；在原 GPA 数字位置旧值淡出、新值淡入。 |
| 临时短条 | 其他非常驻状态如规则上限，用小型状态条显示后淡出。 |

动效时长建议：

| 变化幅度 | 时长 |
|---|---:|
| 小幅变化 | `760ms` 到 `900ms` |
| 中幅变化 | `900ms` 到 `1080ms` |
| 大幅变化 | `1080ms` 到 `1280ms` |

所有动效只影响相关数值区域，不做额外全屏装饰，不显示跳出的数字浮标，不做卡片或状态块弹跳缩放。

多条数值同时变化时，不要全部同时闪。按技能主收益先动，代价后动：

| 变化关系 | 播放顺序 |
|---|---|
| 有恢复也有回退 | 先播放恢复条，再播放回退条。 |
| 有推进也有消耗 | 先播放进度和作品质量，再播放精力和压力。 |
| 有金钱收支 | 先播放金钱，再播放被金钱影响的进度、作品质量或压力。 |
| 有 GPA 修正 | 常规数值动完后，再在原 GPA 数字位置播放旧值到新值的渐变替换。 |
| 只有两个状态变化 | 两条可以相差 `80ms` 到 `120ms` 依次播放。 |

颜色语义：

| 状态 | 颜色处理 |
|---|---|
| 精力上升 | 正向色，条形末端短亮。 |
| 精力下降 | 消耗色，亮度低于压力风险。 |
| 压力下降 | 蓝色动态段，表现为释放感。 |
| 压力上升 | 红色动态段，避免误读为奖励。 |
| 金钱收入 | 蓝色数字动效，表现资源进入。 |
| 金钱支出 | 红色数字动效，先扣款再收益。 |
| 进度上升 | 蓝色动态段，条形移动要最清楚。 |
| 进度回退 | 红色动态段，幅度可见但不夸张。 |
| 作品质量上升 | 蓝色动态段，脉冲比进度更柔和。 |
| 作品质量回退 | 红色动态段，幅度可见但不夸张。 |

## 每个角色的数值反馈

### 普通人：放平心态

按钮文案：别紧张，放松

需要动态变化：

- 精力条上升 `+20`。
- 压力条下降 `-20`。
- 进度条回退 `-10`。
- 作品质量条回退 `-5`。

播放顺序：精力和压力先同步变化，进度和作品质量延迟 `120ms` 回退。

反馈感觉：先给玩家明显的放松感，再让回退作为代价出现。进度和作品质量不要警报化，只做淡色旧值刻度和小幅回退。

### 混得入：原地开摆

按钮文案：我开摆了

需要动态变化：

- 不播放条形动效。

播放顺序：若当前进度超过新上限，课设进度数值可被系统截断，但不播放进度值域上限、课设进度、评图门槛或最高等级的条形动效。

反馈感觉：不是庆祝，而是规则被悄悄改掉。不要为评图门槛、最高等级或课设进度播放额外动效。

### 不吃压力之人：睡醒再说

按钮文案：直接开睡

需要动态变化：

- 精力条大幅上升 `+40`。
- 压力条大幅下降 `-40`。
- 进度条回退 `-15`。
- 作品质量条回退 `-10`。

播放顺序：精力先大幅回升，压力紧跟着下降，进度和作品质量在最后回退。

反馈感觉：恢复感最强，数值滚动可以更饱满。回退条保持低对比，像睡醒后发现图还没画完，不做强惩罚感。

### 设计赋能哥：降维打击

按钮文案：柯布西耶，请赐予我力量！

需要动态变化：

- 进度条上升 `+15`。
- 作品质量条上升 `+20`。
- 压力条上升 `+20`。
- 精力条下降 `-15`。

播放顺序：进度和作品质量快速推进，`100ms` 后压力上升，再 `80ms` 后精力下降。

反馈感觉：主收益要像方案突然成型，条形推进干脆、有力量。压力和精力是代价，要清楚但不要抢走主收益。

### 寒门贵子：逆天改命

按钮文案：我开挂了

需要动态变化：

- 进度条上升 `+20`。
- 作品质量条上升 `+15`。
- 精力条下降 `-20`。
- 压力条上升 `+15`。

播放顺序：进度先推进，作品质量随后提升，精力下降和压力上升在最后一起出现。

反馈感觉：推进感强，像硬把这周往前推了一格。精力和压力的旧值刻度与落点脉冲必须足够清楚，让玩家看见代价。

### 吃满压力之人：背水一战

按钮文案：红眼模式，启动！

需要动态变化：

- 进度条大幅上升 `+25`。
- 精力条下降 `-10`。
- 压力条上升 `+5`。

播放顺序：进度条立即大幅推进，精力下降随后出现，压力上升最后短促脉冲。

反馈感觉：进度条变化最快、最硬。压力只做短促提示，不能把这个技能表现成纯危险状态。

### 未来的老板：钞能力启动

按钮文案：不就是钱吗？

需要动态变化：

- 金钱数字显示 `-¥3000`。
- 进度条上升 `+20`。
- 作品质量条上升 `+20`。
- 压力条下降 `-5`。

播放顺序：金钱先扣减，进度和作品质量随后同步补上，压力下降最后轻亮。

反馈感觉：先让玩家明确“钱花出去了”，再看到方案被资源补齐。压力下降只做轻量收尾。

### 投胎专家：爸妈爆金币

按钮文案：丫够燥的！

需要动态变化：

- 金钱数字显示 `+¥3000`。
- 压力条上升 `+10`。

播放顺序：金钱收入先跳出并滚动到新值，压力上升延迟 `120ms` 出现。

反馈感觉：收入反馈清楚，但压力上升要紧跟出现，避免看起来像纯奖励。

### 基因叛逆者：爸妈救我

按钮文案：救命！

需要动态变化：

- 金钱数字显示 `+¥1000`。
- 压力条上升 `+20`。
- 进度条上升 `+15`。
- 作品质量条上升 `+20`。

播放顺序：金钱先进入，进度和作品质量随后推进，压力上升最后以更明显的低强度脉冲收尾。

反馈感觉：资源进入很有效，但压力反弹是明显代价。压力条的旧值刻度和危险色落点不能太快消失。

### 小镇做题家：回到高中

按钮文案：我是学霸，懂吗？

需要动态变化：

- 进度条上升 `+15`。
- 精力条下降 `-10`。
- 压力条上升 `+10`。
- 个人 GPA 原数字从 `3.12` 渐变为 `3.22`。

播放顺序：进度先推进，个人 GPA 原位置数字渐变随后出现，精力下降和压力上升最后出现。

反馈感觉：进度和个人 GPA 是重点，像完成了一张答题卡。压力和精力作为刷题代价出现，不要比 GPA 数字更抢眼。

### 柯布西耶继承者：爸妈救我

按钮文案：救命！

需要动态变化：

- 金钱数字显示 `+¥1000`。
- 压力条上升 `+20`。
- 进度条上升 `+15`。
- 作品质量条上升 `+20`。

播放顺序：金钱先进入，进度和作品质量随后推进，压力上升最后出现。

反馈感觉：数值变化可以和基因叛逆者一致，但条形风格更克制，像学术资源被接入。UI 里角色名和技能标题必须来自当前角色，不能共用错误角色语境。

## 实现提示

为了让数值条从旧值动到新值，需要在确认按钮执行命令前后保留快照。

```text
before = readVisibleMeterSnapshot(state)
result = performAction(state, "special_skill")
after = readVisibleMeterSnapshot(state)
render()
if result.ok:
  animateChangedMeters(before, after, characterId)
```

需要覆盖的可见数值：

- 精力
- 压力
- 金钱数字
- 课题进度
- 作品质量
- 个人 GPA 原位置数字
- GPA 学期修正原位置数字

GPA 相关变化只在原数字位置做旧值淡出、新值淡入，不使用进度条、临时条或浮动变化量。

## 真实 UI 验收

旧预览脚手架已删除。专属技能动效只在当前真实 UI 链路中验收：

- 从 `web-app/index.html` 进入真实游戏，或使用仍保留的 `web-app/senior-test-copy.html` 做大五结尾回忆相关验证。
- 角色专属技能验收必须渲染真实 `game-shell`，包含真实状态栏、课程栏、角色信息、专属技能按钮和确认弹窗。
- 点击真实专属技能按钮后，先出现真实确认弹窗；确认后调用真实技能结算，再播放对应状态条变化。
- 状态条使用和真实游戏一致的反馈语言：旧值刻度、条形缓慢推进或回退、低透明度扫光、正向蓝色变化段、负向红色变化段；涉及金钱时只显示金钱数字变化动效，涉及 GPA 时只在原 GPA 数字位置做旧值淡出、新值淡入；播放结束后进度条恢复原本颜色。
- 不显示数字弹出、变化量浮标或额外结算文案。
- 深色和浅色主题都必须能看清变化条、旧值刻度和最终落点。

## 可访问性和性能

必须支持 `prefers-reduced-motion: reduce`：

- 数值直接跳到结果值。
- 相关条形只做 `180ms` 到 `220ms` 的颜色高亮。
- 不做滚动数字、位移、缩放或连续闪烁。

性能约束：

- 只动画 `width` 的替代变量、`transform`、`opacity` 和颜色。
- 不动画网格布局、滚动位置或页面尺寸。
- 同一时间只播放一次专属技能数值反馈。
- 每次反馈结束后清理临时标签和图章。
- 确认 UI 打开时只捕获自身遮罩内交互；关闭后必须恢复主界面命中区域。
- 确认 UI 和反馈层不能覆盖或改写 `pendingInteraction` 弹窗按钮的命中区域。

## 验收标准

首版实现通过以下检查：

- 点击可用专属技能按钮后，只打开 app shell 确认 UI，不立刻执行技能。
- 确认 UI 标题总是当前技能名。
- 确认 UI 底部按钮文案按角色表展示。
- 点击确认 UI 底部按钮后，才派发 `perform-action` / `special_skill` 并执行技能。
- 命令失败、取消或关闭确认 UI 时，不播放数值反馈。
- 技能执行成功后，只变化相关数值和进度条，不播放复杂粒子或全屏花哨特效。
- 正负变化、压力升降、金钱收支都能被玩家看懂。
- 深色和浅色主题都能看清数值变化。
- 开启减少动态效果后，仍有轻量确认反馈。
- 打开、关闭或取消确认 UI 不改变 `GameState`、不写入存档、不改变 `pendingInteraction` 流程。
