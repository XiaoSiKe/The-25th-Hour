## 硬边界

- UI 只读取 `toViewModel(state)` 产物，只派发既有 command。
- 组件不得直接读取、计算或修改 `GameState`、数值门槛、路线结果、成就或结局。
- 阻塞流程只来自 `GameState.pendingInteraction`；app shell 临时 UI 不得冒充规则弹窗。
- 占位入口必须直接显示预留、待开放、接口未接入或链接待填写，不展示假数据。
- 事件、结局、属性、路线、题库和系统标题正文读取 `../../docs/` 与 `../../web-app/game/data.mjs`，UI 文档不得重写。

## 当前口径

当前本轮允许非视觉的 UI 代码结构收敛和明确 bug 修复。本轮范围是：

- 修复不改变页面展示口径的接线、状态来源、命令映射和代码颗粒度问题。
- 拆分过大的 UI 配置或渲染文件，降低后续维护成本。
- 保持现有玩法、数值、事件、路线、结局和存档语义不变。
- 用户已确认手机端不做完整游玩适配；手机端只保留开场入口和低频信息浏览，并在开始或读档进入游戏时提示使用电脑端。
- 旧的小屏主流程、行动区、状态仪表、日志、角色课程、读档、建档表单和音乐播放器手机布局适配不再保留；手机端不复用桌面开始页 DOM，后续只允许新增手机入口提示、分享预览或低频信息页。

凡会改变页面布局、展示状态、交互节奏、视觉密度、弹窗表现或未确定 UI 显示问题的改动，都必须先让用户确认。按 PNG 全量重做页面、排行榜接口和 IndexedDB 存档迁移仍需另行确认。

## 开发顺序

1. 读 `DESIGN.md` 与 `png-reference-index.md` 确认视觉约束。
2. 确认本轮改动不改变游戏逻辑、页面布局或既有交互节奏。
3. 读信息架构、组件清单、VM 契约和系统入口状态。
4. 读 `../shared/ui-command-mapping.md` 确认按钮只能派发哪些 command。
5. 执行本文“开发前检查”。
6. 改代码后运行模拟器验证和本地页面检查。

## 开发前检查

进入 UI 实现前必须满足：

- PNG 参考只作视觉、布局、层级和状态验收，不作规则源；主流程普通周桌面浅色和深色必须对齐 `png-reference-index.md` 标记的两张母版。
- UI 只读 `toViewModel(state)`，只派发 `../shared/ui-command-mapping.md` 已列 command；缺 command 时先补命令层。
- 系统入口读取 `systems.entries` 与 `system-entry-status.md`，不在组件内维护第二份入口状态表。
- 占位、禁用、接口失败和链接缺失原因必须直接可见，不展示假榜单、假投稿结果、假语言切换或假成就。
- 专属技能确认层是 app shell 临时确认遮罩，不写 `pendingInteraction`；确认后才派发行动 command。
- 手机端只保留开场入口、低频信息浏览和电脑端提示，不承载完整主流程游玩。
- UI 任务不修改玩法、数值、事件、路线、结局、存档语义、排行榜计分口径或已确认正文。

若发现行动收益、属性初值或门槛异常，先记录问题并让用户统一确认。路线目标模拟达成率已接受为验证覆盖限制，不再作为 UI 开发阻塞项。

## 验收口径

- `npm run verify:all` 通过。
- 新增或修改的 UI 模块可被浏览器加载，无未处理的语法错误。
- 开场、角色选择、主流程、系统弹窗和成就提示至少完成一次人工或浏览器检查。
- 文档没有再复制同一张入口状态表、VM 字段表或组件清单全文。
