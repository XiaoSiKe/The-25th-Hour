# 历史决策归档

本文只记录仍有解释价值的历史背景，不作为规则源、文档索引或待办清单，不重复维护数值、概率、门槛或正文内容。

现行权威入口和冲突处理统一读取 `README.md`。如果本文与当前权威入口冲突，以当前权威入口为准。

## 保留背景

### 事件体系收束

- 随机事件体系按 `普通随机事件 / 交互事件 / 模型周事件 / 万里路事件` 管理。
- 固定流程事件和实习期间短事件按状态机或实习周次读取，不进入随机池。
- AI 相关内容不拆成主系统，只作为事件语境、AI 相关经历和后期路线条件。
- 事件配置采用结构化字段，避免事件标题、正文和规则读取混在一起。

### 竞赛与作品集

- 竞赛奖金、简历记录和作品集分开结算，避免竞赛结果反向膨胀作品集。
- 玩家可见层只展示奖项和奖金提示；简历写入、成就判定等由后台结算。

### 实习价值

- 建筑工作路线读取累计 `实习价值`，用于表达履历厚度。
- 实习申请不再读取最高已完成实习档位；累计 `实习价值` 只服务建筑工作路线等后期读取。
- 实习过程反馈收束为录取、拒绝和三周短事件，不再拆入职、结束总结或简历写入弹窗。

### 开发冻结

- 首版不再新增主系统，只推进实现落地、内容补全、数值调参和体验打磨。
- `GameState` 是唯一真相源；时间推进走显式状态机；数值变化走统一结算器。
- 固定 seed 必须能复现事件抽取、考试抽题、实习录取、留学申请和岗位投递内部判定。

### 可执行内核迁移

- 当前 `web-app/game/*` 是可玩规则标准；`simulator` 是迁移到正式 `game-core` 前的验证适配层，不是第二套规则源。
- 模拟结论只用于发现实现或调参问题；稳定规则仍必须回到 `systems.md`、`numbers.md` 和内容文档。
- 后续应从 `web-app/game/*` 逐步抽出正式 `game-core / game-data`，再删除不再需要的模拟壳。

## 不再维护

- 事件、结局、题库、角色、导师、课程和路线正文。
- 数值、概率、门槛和结算表。
- 文档索引、权威入口和冲突优先级。
- UI 保留清单、系统入口状态和精细 UI 替换顺序。
- 技术实现步骤、存档字段、部署验收和当前校验日志。
