# 运行时资源缓存与媒体播放策略

最后更新时间：`2026-07-28 +08:00`

本文是部署方案下的专项技术方案，只细化运行时资源加载、后台缓存、音频播放、结尾动画播放和免费额度风险，不改变 `technical-architecture.md` 已确定的部署边界、规则边界和排行榜边界。

核心目标是保证玩家体验丝滑、不卡顿。资源缓存服务表现层和加载体验，不参与游戏规则、数值结算、路线判定或结局判定。

## 已拍板结论

- 不再直接进入游戏开始页。页面刚打开时立即显示加载页；启动页 `WOFF2` 字体子集和加载页小图允许在有界时间内准备。
- 启动页字体子集只覆盖加载页和全屏提示所需文字；完整游戏字体在加载页出现后后台排队。
- 加载页面必须阻塞等待启动门资源：桌面关键首屏图片、支持二维码 `2` 张、失败结局插图 `5` 张、创业结局插图 `1` 张、大一上/大一下作品集展板 `2` 张，以及大一学年首曲 BGM `1` 首；大一剩余 `7` 首和失败结局绑定曲 `5` 首在进入游戏后按低优先级队列预热。启动门失败使用有界重试，不能让加载页永久卡住。
- 最终 UI 图标不再以单图粒度请求；`confirmed-icons` 与 `unmapped-icons` 下的 `728` 个源图在构建时合成 `1` 张 WebP atlas，运行时按 manifest 坐标渲染。
- 玩家进入游戏页面后，后台立即连续预热后续学年音乐，并提前排队结尾动画页面和动画运行时 CSS / JS；本局普通结束曲和歌词在结局曲选定后解析成最终 R2 URL，并通过 `queueSelectedEndingMusicPreload()` 预热单首资源，后期资源冲刺会再次确认它已排队，不等到结尾回忆入口或实际播放时才首次请求。
- 不等到资源要播放时才首次请求。音频和结尾动画入口都必须提前预热。
- 音频采用当前曲可播、下一首预热、下一学年首曲提前准备的策略。
- 结尾回忆采用同源动画页嵌入，场景图片使用优化后的 WebP，不再维护 MP4 低清/高清版本。
- 大文件主源默认走 `Cloudflare R2`；非启动门音频、普通/路线结局图和结尾回忆 WebP 场景图都必须在 R2 版本化路径可访问，创业结局插图额外镜像到国内 CDN。
- 阿里云承载 HTML / JS / CSS、启动字体子集、加载页基础样式和少量站点源高优先资源；生产入口的启动门国内段镜像到 `assets-cn.25thgame.vip` 国内 CDN，支持二维码、失败结局插图、创业结局插图、大一上/大一下作品集展板，以及启动门首曲和进场后待预热的其余 `12` 首 BGM 都走国内 CDN；其他作品集展板、普通/路线结局插图、结尾回忆场景图以及普通结局歌曲和 `.lrc` 歌词仍走 `Cloudflare R2`。
- 加载页壳层不能依赖 R2 才能显示；R2 变慢时，加载页必须稳定展示并给出进度，失败资源不能让进度条永久卡住。
- `Workers + D1` 只做排行榜读取和提交，不参与正常游玩循环。
- 本地存档继续使用 `IndexedDB`；服务器不保存完整玩家存档。

## 架构边界

```text
玩家访问 `arch.25thgame.vip`
-> 加载 HTML / JS / CSS 游戏主程序
-> 先完成启动页 WOFF2 字体子集加载
-> 显示加载页面
-> 加载页面并行预热启动门图片和启动门 BGM
-> 进入开始页或游戏页面
-> 游戏页面先按失败清单重试启动门剩余失败资源
-> 游戏页面后台连续预热后续学年音乐、结尾动画页和动画运行时依赖
-> 本局结局曲选定后预热对应普通结束曲和歌词
-> 进入大五时本局结束曲应已命中或正在重试，不由结尾回忆入口首次加载
-> 浏览器按阶段从国内 CDN 或 R2 拉取尚未命中的音乐和非首屏大图
-> 浏览器 Cache / Service Worker 缓存已读取资源
-> 游戏主循环、行动结算、事件抽取和结局判定在本地完成
-> 结局提交或查看榜单时调用 Workers
-> Workers 读写 D1 排行榜摘要
```

任何缓存失败都不得改变游戏规则结果。R2 媒体资源加载失败时，允许表现降级，但不能破坏继续游戏、读档、结局展示和本地分数累计。

## 资源分层

| 层级 | 内容 | 加载策略 | 体验要求 |
|---|---|---|---|
| `font-gate` | 启动页 `WOFF2` 字体子集，包含加载文案、全屏提示和进度数字 | 加载页出现后有界准备，完整字体后台排队 | 加载页不能因为远程资源慢而保持黑屏 |
| `startup-gate` | 桌面 `20` 张启动门图片 + 大一首曲 BGM `1` 首；移动端 `10` 张入口图片；桌面图中 `1` 张 UI atlas 覆盖 `728` 个最终 UI 源图 | 加载页期间完成；图片和首曲从启动门尝试开始并行预热；图片并发上限为 `4`，音频为 `2`；上次失败项会在同版本同端优先加载 | 正常完成后进入开始页或读档游戏页；失败项不写完成标记，写入失败清单并进入后台重试 |
| `background-all` | 大一剩余 `7` 首、失败结局绑定曲 `5` 首、后续学年音乐、剩余作品集展板、基准结局图、结尾动画页、动画运行时 CSS / JS 和剩余场景图 | 进入游戏页面后立即后台连续预热；音频并发上限为 `3` | 不等玩家临近系统才首次请求，但不得抢占首屏与当前交互资源 |
| `current` | 当前学年音乐、当前界面图片、当前系统图标 | 使用前加载 | 必须保证当前交互稳定 |
| `next` | 下一首歌、下一学年首曲、即将进入系统的图片 | 后台低优先级预热 | 不抢当前播放和操作资源 |
| `ending` | 结局图、本局选定的结束曲与歌词、结尾回忆动画页 | 结局曲选定后预热单首结束曲和歌词；进入大五时确认本局结束曲已提前排队，大五后期开始强化结尾动画入口 | 结局情绪段不能黑屏或长时间等待 |
| `optional` | 非必要预览素材 | 不阻塞启动门槛 | 只能锦上添花 |

## 首屏策略

首屏目标不是立刻展示开始页，而是让玩家看到稳定的字体、完整的加载页和不卡顿的开始体验。

- 页面刚打开时先显示加载页，不渲染开始页。
- `font-gate` 和加载页壳层有界准备，加载页等待 `startup-gate`。
- `startup-gate` 的桌面图片请求覆盖关键首屏图片：开始页背景 -> 最终 UI 图标 atlas `1` 张 -> 支持二维码 `2` 张 -> 角色卡背面 -> 固定事件图 -> 失败结局插图 `5` 张 -> 创业结局插图 `1` 张 -> 大一上/大一下作品集展板 `2` 张 -> 暑假写生图。
- 阿里云生产入口的启动门图片分流固定为：加载壳时钟走站点源；开始页背景、UI atlas、支持二维码、角色卡背面、固定事件图、失败结局插图、创业结局插图、大一上/大一下作品集展板和暑假写生图走国内 CDN；剩余 `6` 张作品集展板、其他普通/路线结局插图和结尾回忆场景图走 R2。
- UI 图标的源图颗粒度仍然完整保留：`728` 个最终 UI 源图包含 `675` 个 `confirmed-icons` 和 `53` 个 `unmapped-icons`。`ui-icon-atlas-manifest.mjs` 逐个记录源图到 atlas 的 `x/y/width/height`，`renderUiIcon()` 按原始图标路径查坐标后渲染。
- 图片和桌面启动门首曲从启动门尝试开始同时预热；BGM 仅包含大一学年首曲 `1` 首。大一剩余 `7` 首和失败结局绑定曲 `5` 首会在进入游戏后依序后台预热，仍映射到国内 CDN。移动端只承载入口页，不阻塞这些 BGM。
- 浏览器本地记录 `startup-gate` 已完成时，仍要复用同一份 `startup-gate` 清单做本次会话轻量解码/可播校验；该记录只减少等待时间，不代表本次 DOM 首屏图片已经完成解码。
- 启动门资源使用有界重试。首次启动以 `12` 秒为目标等待预算，`30` 秒是不可突破的最终上限；失败或超时项不能永久占住加载队列。国内 CDN 资源失败时重试同一国内 CDN URL，不切换到 R2，原本走 R2 的资源则重试 R2 URL；本次不写入完成标记，并按 `APP_VERSION + 国内 CDN 域名 + R2 域名 + 桌面/移动端` 写入失败清单。进入游戏页面后优先后台重试，下一次启动门也会优先处理这些失败项。
- 后续学年音乐不得阻塞启动门；普通结束曲和歌词在本局结局曲选定后预热单首资源，进入大五时应已命中或处于失败重试队列；结尾回忆动画帧不再整体阻塞启动门，进入游戏页面后仍会提前预热动画 HTML、CSS、`scenes.generated.js`、`main.js`、GSAP 和剩余场景图。
- 如果 Service Worker 尚未安装成功，游戏仍必须能在线正常运行。

## 音频缓存策略

音频目标是学年切换和手动切歌不卡顿。

当前运行时音乐使用带内容 hash 的 `.m4a` AAC 文件；R2 和本地静态服务必须按 `audio/mp4` 返回。

```text
启动门
-> 大一学年首曲至少完成可播预热
-> 进入游戏页面后重试启动门失败音频
-> 后台低优先级预热大一剩余曲目和失败结局绑定曲
-> 后台预热大二全部曲单
-> 后台同批预热大三 / 大四 / 大五各前 2 首
-> 后台同批补齐大三 / 大四 / 大五剩余曲目
-> 结局曲选定后预热本局普通结束曲和歌词
-> 进入大五/后期资源冲刺时确认本局普通结束曲和歌词已排队预热
-> 当前曲播放稳定后继续预热下一首
```

具体规则：

- 当前播放曲目可以正常加载和播放。
- 下一首曲目在当前曲播放稳定后低优先级预热。
- 下一学年第一首不能等到进入下一学年时才首次请求。
- 大一首曲在启动门加载；进入游戏后后台预热大一剩余曲目和失败结局绑定曲。进入大二、大三、大四、大五前，对应学年曲单应已在后台预热。
- 普通结束曲不在进入游戏页面后全量预热；当前实现由 `queueSelectedEndingMusicPreload()` 在结局曲选定后把本局单首结束曲和对应歌词解析为 `https://assets-apac.25thgame.vip/assets/v1/...` 最终 URL 后预热，进入大五/后期资源冲刺时只做同一首歌同一 URL 的补强确认。
- 后台学年 BGM 使用小批次同步：先补齐大一剩余曲目和失败结局绑定曲，再预热大二全量，随后合并未来学年前 `2` 首与剩余曲目；正常网络背景 BGM 并发上限为 `3`，弱网或省流量模式会自动降到更低并发。
- 学年切换时，如果新曲尚未准备好，优先保持上一首或做短暂过渡，不让界面卡死。
- 不给全部音频统一使用无节制的 `preload="auto"`。
- 不在开局缓存所有学年音乐；开局只缓存大一首曲。

音频加载失败只影响音乐表现，不影响行动选择、周结算、事件弹窗、路线推进或存档。

## 结尾动画策略

结尾回忆动画是情绪高点，不能等玩家点击播放时才首次加载。现有玩家可见加载文案继续使用“正在整理毕业相册，请稍后……”这一类游戏内表达，不使用技术文案。

正式游戏通过同源 iframe 嵌入 `/hyperframes/ending-memory/index.html?embedded=1&play=1`。动画页读取 `scenes.generated.js`，按顺序播放 108 张优化 WebP 场景图；不再生成、上传或播放 MP4。

预热时机：

```text
进入游戏页面
-> 后台排队结尾动画 HTML / CSS / scenes.generated.js / main.js / GSAP 请求

进入毕业典礼 / 毕业照阶段
-> 强预取结尾动画 HTML 和运行时依赖
-> 浏览器按动画页清单请求 WebP 场景图

玩家点击播放
-> 直接嵌入动画页播放
-> 动画完成或允许跳过后进入结局系统
```

播放标准：

- 不依赖 MP4、poster 或媒体播放元数据。
- 动画页 HTML 预取失败时，允许继续进入动画页；失败次数达到阈值后不阻塞结局流程按钮。
- 动画运行时依赖提前 `prefetch` 并 `force-cache` 请求；失败只影响后续重试，不改变结局流程。
- 场景图片必须使用 WebP，并保持单图体积尽量低于 150KB。
- 动画加载失败时，允许跳过动画或进入结局页降级，不得卡死。

## 图片和图标策略

- 桌面启动加载页必须阻塞预热 `20` 张启动门图片和大一首曲 BGM `1` 首；移动端启动门阻塞 `10` 张入口图片且不阻塞 BGM。UI atlas 覆盖 `728` 个最终 UI 源图。阿里云生产入口中，启动门和进场后待预热的 `13` 首 BGM 都保留在 `assets-cn.25thgame.vip`，避免首屏减负后反而改走 R2。
- 图标 atlas 在构建时生成，不在玩家设备上逐次裁剪文件。浏览器只请求 atlas 图片；页面里的每个图标通过 SVG `viewBox` 指向 atlas 中的固定坐标区域。
- atlas 渲染元素是 `.ui-icon-atlas` SVG，不是旧的 `img`。任何图标容器的尺寸、滤镜和对齐 CSS 都必须覆盖 `.ui-icon-atlas`，保证本地游玩和线上部署使用同一套显示策略。
- 进入游戏页面后，桌面端不再重复请求已命中的启动门图片；后台重点预热后续学年音乐、剩余后台图片和结尾动画页；本局普通结束曲和歌词在结局曲选定后预热，后期只确认同一首歌已排队。
- 图片图标预热服务表现层，不得参与 `GameState`、路线判定、结局判定或排行榜计分。
- 启动门关键图片和首曲加载失败时优先停留在启动门修复重试；首次启动在 `12` 秒目标预算后保存失败清单并放行进游戏，`30` 秒保留为最终上限，非启动门图片图标加载失败时允许继续游戏，不能阻塞命令层或状态机。
- 图片上线格式优先使用 `webp / avif`；首版先处理大图和高频图，不要求一次性重做全部素材管线。

## 浏览器缓存和 Service Worker

首版建议使用轻量 Service Worker，只解决运行时资源缓存，不做完整离线 PWA。

缓存策略：

| 资源 | 策略 |
|---|---|
| HTML | `network-first`，失败时回退缓存，避免长期卡旧版本 |
| `/version.json` | `no-store`，启动门快速读取最新版本声明 |
| JS / CSS / WOFF2 字体 / 核心 UI 图标 | 版本化后 `cache-first` |
| R2 图片 / 音乐 / 视频 | 版本化后 `cache-first` |
| Workers 排行榜接口 | `network-only`，失败时前端降级 |

启动门额外承担版本门槛：当前前端版本为 `V20-20260728`，版本号只使用 `Vn-YYYYMMDD` 格式；内容更新前运行 `npm run version:bump`，脚本会把版本序号加 1 并同步版本清单与运行时缓存名。若 `/version.json` 声明的 `appVersion` 或 `minSupportedVersion` 高于当前包，玩家会停留在启动门并看到“检测到最新版本，正在更新游戏资源...…”，前端清理 runtime cache 和启动预加载完成标记后刷新页面。该流程不删除 IndexedDB 成就/结局数据，也不删除 D1 排行榜数据。

R2 资源路径应带版本号：

```text
/assets/v1/audio/...
/assets/v1/images/...
/assets/v1/optimized/assets/结尾回忆走马灯图片/...
```

R2 版本化静态资源建议使用长缓存：

```text
Cache-Control: public, max-age=31536000, immutable
```

HTML 入口和主程序运行时都应为 `https://assets-apac.25thgame.vip`、`https://assets-cn.25thgame.vip` 和结尾动画依赖的 `https://cdn.jsdelivr.net` 提前写入 `dns-prefetch` / `preconnect`。`assets-cn.25thgame.vip` 只承接阿里云生产入口的启动门国内段、大一上/大一下作品集展板、创业结局插图和启动门 BGM，不替代剩余作品集展板、其他普通/路线结局插图、结尾回忆场景图或其他 R2 资源。

资源更新时递增版本目录，例如从 `/assets/v1/` 切到 `/assets/v2/`。不要覆盖同名大文件后依赖浏览器自然刷新。

生产构建后执行 `npm run verify:production-r2-heads`，用公开生产 R2 域名抽样 `HEAD` 检查 R2 侧资源是否可访问，并对 `arch.25thgame.vip` 抽样校验普通结局曲与歌词的 CORS 头。阿里云构建会额外把启动门国内段复制到 `.aliyun-output/static/assets/v1/` 并写出 `startup-domestic-assets.json`，上线前应确认该目录同步到 `assets-cn.25thgame.vip` 对应源站。

## 免费额度和容量口径

以下数字用于上线容量判断，不作为账单承诺；上线前以平台控制台和官方文档为准。

- R2 免费层按月提供 `10 GB-month` Standard 存储、`1,000,000` 次 Class A 操作、`10,000,000` 次 Class B 操作，公网 egress 免费。玩家读取图片、音乐、视频主要消耗 Class B。
- Workers Free 提供 `100,000` 次请求/天。排行榜只在提交分数、读取榜单和重试待提交分数时请求。
- D1 Free 提供 `5,000,000` rows read/天、`100,000` rows written/天、`5 GB` 总存储。排行榜查询必须限制返回数量并建立索引，避免全表扫描。
- 阿里云站点输出不包含大音乐库、素材源图和生成工程源文件；大文件保持在版本化资源域名，避免主站部署和缓存失控。

估算口径：

- 每名玩家每月玩 5 次时，如果缓存设置正确，后续重复游玩会大量命中浏览器缓存。
- UI 图标 atlas 后，桌面冷启动核心阻塞图片请求口径为 `20` 张，其中最终 UI 图标只占 `1` 次 atlas 请求；进入游戏后仍排队完整后台清单，已命中的图片会直接复用缓存。
- 首版可按每名玩家每月 `250-900` 次 R2 Class B 的中性偏保守口径估算，主要波动来自音频、视频 Range 请求、清缓存和重试。
- R2 每月 `10,000,000` 次 Class B 可支撑约 `11,000-40,000` 名每月玩 5 次的玩家。
- 如果资源命中率更好，可支撑人数更高；如果清缓存、换设备、无痕模式、视频重复 Range 请求较多，可支撑人数更低。

官方参考：

- Cloudflare R2 Pricing: `https://developers.cloudflare.com/r2/pricing/`
- Cloudflare Workers Pricing: `https://developers.cloudflare.com/workers/platform/pricing/`
- Cloudflare D1 Pricing: `https://developers.cloudflare.com/d1/platform/pricing/`

## 并发风险

本游戏首版没有常驻游戏服务器，也不让每周结算请求云端，因此不存在传统意义上“游戏服务器并发打爆”的主风险。

主要风险来自：

- R2 读取次数被大量玩家同时消耗。
- Workers 排行榜请求超过每日免费额度。
- D1 查询没有索引导致 rows read 快速增长。

控制手段：

- 非启动门大素材主要走 R2；阿里云生产入口的启动门国内段复制到 `assets-cn.25thgame.vip`，作品集展板是国内 CDN 例外资源：大一上/大一下阻塞启动门，其余 `6` 张进入游戏后走 R2 后台预热；创业结局插图和全部 `13` 首首年/失败结局 BGM 作为国内 CDN 例外资源，其中只有大一首曲保留在核心启动门，其余在进入游戏后低优先级预热；其他普通/路线结局插图和结尾回忆场景图保留 R2，首屏壳层资源留在阿里云站点源。
- 资源缓存命中后重复游玩不再重新拉取完整文件。
- 排行榜接口限制频率、限制返回条数、使用索引。
- 排行榜失败时前端降级，不阻塞结局页和本地游戏。

## 明确不做

首版不做：

- 在加载页阻塞全部音乐和全部视频下载；启动门只阻塞大一学年首曲。
- HLS 分片视频。
- 完整离线 PWA。
- 云端存档同步。
- 每周结算云端化。
- 让高清视频阻塞结局播放。
- 让排行榜失败影响结局展示。

## 接入顺序

1. 建立资源版本路径和 `ASSET_BASE_URL` 口径。
2. 把资源清单分成 `font-gate`、`startup-gate`、`background-all`、`current`、`next`、`ending`、`optional`；其中加载页壳层、启动字体和结尾动画 HTML 留在阿里云站点源，阿里云生产入口的启动门国内段走国内 CDN，大一上/大一下作品集展板、创业结局插图和启动门 BGM 走国内 CDN，剩余作品集展板、其他普通/路线结局插图、结尾回忆场景图和其余优化资源走 R2。
3. 接入轻量 Service Worker 和版本化 cache-first 策略。
4. 调整音频加载：启动门加载大一学年首曲，进游戏后先低优先级预热大一剩余曲目和失败结局绑定曲，再预热大二到大五曲单；结局曲选定后预热本局普通结束曲和歌词，并保证结尾回忆入口不承担首次加载。
5. 进入游戏页面后连续排队后续学年音乐、结尾动画 HTML 和动画运行时依赖；启动门失败资源进入持久失败清单并停留在启动门自动重试，首次启动在 `12` 秒目标预算后先放行并在进入游戏后后台重试，`30` 秒仅保留为最终上限。
6. 维护结尾回忆 WebP 场景图和 `scenes.generated.js` 映射。
7. 在阿里云生产构建后执行公开 R2 样本 `HEAD` 检查，并确认阿里云输出里的 `assets/v1/startup-domestic-assets.json` 与国内 CDN 源站一致。
8. 接入排行榜时保持 network-only 和失败降级。
9. 用浏览器网络面板验证重复游玩缓存命中。

## 验收标准

- 页面刚打开后加载页稳定展示；加载页文字、全屏提示和进度数字不发生字体闪烁。
- 加载页完成前，桌面启动门 `20` 张图片按固定优先级完成预热；其中 `1` 张 UI atlas 必须覆盖 `728` 个最终 UI 源图，创业结局插图和大一上/大一下作品集展板必须保留在启动门；并行完成大一学年首曲的可播预热。其余大一 `7` 首与失败结局绑定曲 `5` 首在进入游戏后低优先级预热。移动端启动门预热 `10` 张入口图片且不阻塞 BGM。
- `startup-gate` 正常完成后写入完成标记；若关键图片或启动首曲单项失败或超时，不写入完成标记，失败项写入同版本同端失败清单，启动门显示资源修复提示并只重试剩余失败资源；首次启动在 `12` 秒目标预算仍有失败项时先放行，进入游戏后优先后台重试失败项，`30` 秒是不可突破的最终上限。
- 玩家进入游戏页面后，后续学年音乐、结尾动画页和动画运行时依赖立即后台连续预热；结局曲选定后本局普通结束曲和歌词开始预热，进入大五时应已完成或处于重试队列。
- 学年切换时音乐不断档；最差也不能卡住按钮、结算弹窗或主界面。
- 结尾动画入口出现前，动画 HTML 已开始预取，其余场景图由后台队列和动画页按清单继续请求，路径映射有效。
- 玩家点击结尾动画后，不能出现长时间黑屏或无反馈。
- 同一设备、同一浏览器重复游玩时，首屏壳层资源和大部分 R2 图片、音乐命中缓存。
- 正常网络下后台 BGM 预热可用更高并发；弱网、省流量模式或低下行速率设备自动降并发，不因抢资源导致当前界面图片和当前音乐更容易失败。
- `npm run verify:production-r2-heads` 会触发公开生产 R2 样本 `HEAD` 检查；样本访问失败时应停止发布并先修资源路径或上传状态。
- 排行榜接口失败时，结局页、音乐、结尾动画、本地存档和分数展示仍正常。
- R2 迁移完成后，阿里云站点输出不包含大音乐库、素材源图和生成工程源文件；启动字体子集、结尾动画 HTML 和少量站点源资源除外。
- D1 排行榜查询有限制返回数量，并对常用排序和过滤字段建索引。

## 当前过渡状态

当前实现已经接入启动字体子集、启动门图片、启动门 BGM、结尾回忆动画图片和 UI 图标 atlas 的统一清单。后续修改资源时，必须同步运行 `npm run build:ui-icon-atlas`、`node hyperframes/ending-memory/tools/build-ending-memory-manifest.mjs` 与 `npm run verify:ui-icon-atlas`，并更新代码清单、优化资源 manifest 和本文档，避免重新出现“源图数、请求数、音乐数”口径不一致。

R2 资源域名、版本目录和 Service Worker 接入完成后，阿里云站点输出只保留首屏壳层资源、启动字体子集和必要站点源资源；音频、视频、剧情大图、作品集大图和结局图不进入主站构建包。
