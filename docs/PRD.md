# 第二十五小时：建筑生模拟器 PRD

本文是项目的高层产品契约，只定义游戏是什么、不是什么、核心体验、系统边界、失败通关口径和文档分工。流程细则读取 `systems.md`，数值、门槛、概率和结算表读取 `numbers.md`，事件与结局正文读取内容文档，工程实现读取 `technical-architecture.md`。

## 产品定义

一款让玩家重新经历五年建筑学院青春的人生模拟器。

游戏不是纯建筑设计训练模拟器。建筑专业负责承载时间分配、压力、成长和人生分岔；玩家真正管理的是行动机会、精力、压力、金钱、课题成果和后期方向。

一句话气质：玩家不是在扮演“天才建筑师”，而是在五年的时间、金钱、精力、压力、图纸、路线选择和时代变化里，把一个普通学生慢慢推到毕业那天。

## 核心体验

- 每周行动机会有限，选择的重量来自取舍。
- 评图是每学期最核心的结算，进度回答“有没有做完”，作品质量回答“做得好不好”。
- 普通毕业应稳定可达，强路线保持稀有，中途失败有压迫但不高频。
- AI 是时代语境和后期路线条件，不是第二套主系统。
- 结局只读取一个主结局加一句状态收尾，不做多结局拼贴。
- 整体气质允许好笑，但底色不是纯搞笑；允许沉重，但不把玩家按进苦情。理想味道是：荒诞里有真实，狼狈里有一点温柔。
- Slogan：黄色的树林里不止分出两条路，少年，你的选择是什么呢？

## 文案原则

- 克制，不故意煽情。
- 真实，不把建筑学院写成纯爽文，也不把失败写成审判。
- 事件文本短，结局文本可以更完整，但都要留有余味。
- 文案可以嘴欠，但不能让系统逻辑变含糊。
- 涉及数值、路线和条件时，文本可以有文学性，规则必须清楚。
- 大一到大三少写大四焦虑和大五告别；大四、大五再逐渐加重路线感和回望感。

## 体验与界面原则

目标玩家主要是对建筑学院、设计课、评图、赶图和毕业分岔有共鸣的人，也包括想体验建筑生五年取舍的普通玩家。游戏按长时间游玩的网页界面设计，玩家需要快速判断状态、选择行动、处理阻塞事件，并理解每次选择带来的资源变化。

界面原则：

- 状态判断快于装饰表达。
- 每个入口都说明可用、置灰或占位原因。
- 像素体素和工程制图语言服务识别，不替代规则说明。
- 不做成普通 SaaS 仪表盘、营销落地页、抽象蓝图海报或大面积低密度卡片页。
- 避免装饰性渐变、漂浮光斑、过度玻璃拟态、大圆角堆叠，以及把内部 ID、seed、phase 当作正式玩家信息。
- 文字和背景保持足够对比度，状态不能只靠颜色表达；键盘焦点必须可见，动效尊重 `prefers-reduced-motion`，成就提示、弹窗和系统入口不得阻塞屏幕阅读器理解当前流程。

UI 的技术接线原则不在 PRD 维护，统一读取 `technical-architecture.md` 和 `../ui-work/`。

## 主系统契约

首版主系统固定为：

- 开局档案、角色、导师和大学课程。
- 周行动、课题、模型周、赶图周和评图。
- 精力、压力、金钱、GPA、作品集和个人简历。
- 随机事件体系、固定流程事件、实习期间短事件和毕业事件。
- 商店、竞赛、实习、建筑生的万里路和暑假写生。
- 后期路线、失败通关、人生结局和成长成就。
- 音乐、结尾回忆、排行榜和支持页面等表现或外围系统。

首版不再新增主系统。后续工作只进入四类：

- 实现落地：状态机、配置表、结算器和 UI 流程。
- 内容补全：事件、题库、结局文本、课程、角色和岗位内容。
- 数值调参：基于跑局模拟调整收益、门槛、权重和失败率。
- 体验打磨：调整展示顺序、提示文案、置灰逻辑和反馈节奏。

## 流程边界

游戏从开局档案与角色选择进入固定开场，再按学年、学期和周推进。每个学年处理导师与课程选择；每个学期推进课题、周行动、事件、评图和结算；后期路线只在大五阶段形成正式参与；大五下评图结果决定尾声分支：完成毕业设计后进入毕业典礼、结尾回忆和结局结算，未完成毕业设计则从评图结果页直接进入延毕结局。

流程顺序、周内触发、评图展示顺序、路线考试时机和尾声流程以 `systems.md` 为准。PRD 不维护具体周次、行动次数、阈值、抽取权重或 UI 步骤。

## 系统边界

- 角色：提供开局差异、被动特质和专属技能；不新增角色专属资源或额外行动槽。
- 导师：影响阶段任务和事件语境；不设置认可度、好感度、独立关系条或隐藏路线分。
- 大学课程：轻量系统，服务属性收益、GPA 修正和事件语境；不展开为独立主玩法。
- 事件：随机池、固定流程事件和实习期间短事件分工清楚；课堂、导师、AI、地点只做语境标签。
- 建筑生的万里路：成长副系统，消耗资源并触发地点事件；不进入作品集。
- 暑假写生：固定节点，只提供属性与事件收益；不扩成暑假自由行动周。
- 商店：轻量修正系统，不做库存、背包、耐久或 build 系统。
- 竞赛：读取已完成课题作品；奖金、简历记录和作品集分开结算。
- 实习：概率录取、持续周结算、写入简历并计入路线门槛；不占周行动槽。
- 后期路线：每局最多正式参与一个方向，正式参与后不跨路线补读结局。
- 结局：统一由结局解析器读取，其他系统不得提前写死人生结局。

具体系统规则与职责边界读取 `systems.md`。

## 成长与路线

长期成长围绕角色六维、精力、压力、金钱、个人 GPA、作品集、个人简历和 AI 相关经历展开；学期课题只保留进度与作品质量两个临时值。作品集、竞赛、实习、万里路和课程之间保持职责分离，不互相替代。

后期路线组固定为：

- 升学路线组
- 体制内路线组
- 建筑工作路线组
- 转行路线组

路线正式参与只在大五阶段由玩家主动完成报名、申请、投递、考试或确认后形成。若毕业前仍未正式参与方向，结局系统跳过路线结果，读取状态毕业结局。若已正式参与方向，结局只按已参与方向判定；失败后优先读取该方向专属回落，不跳到其他路线补救。

路线门槛、申请概率、考试折算和结局读取条件读取 `numbers.md` 与 `endings.md`。

## 失败与通关

只有完整读完五年、未触发中途失败且完成毕业设计，才算成功通关。

中途失败只保留少量明确条件：

- 生活费断裂
- 压力失控
- 挂科两次劝退
- 被迫停学

结局读取优先级固定为：

1. 中途失败
2. 毕业失败——你被延毕了！
3. 已正式参与路线结果
4. 状态毕业

若大五下毕业设计未完成与连续挂科同时发生，优先读取 `毕业失败——你被延毕了！`。该分支在评图结果页确认后直接进入结局页面，不触发毕业回忆。强路线只是高门槛成功结果，不是额外失败条件。

失败阈值、毕业设计完成条件、状态收尾口径和结局表读取 `systems.md`、`numbers.md` 与 `endings.md`。

## 文档边界与冲突处理

- `CONTEXT.md` 是领域词汇表，只定义术语。
- `PRODUCT.md` 是产品登记入口，不维护规则正文。
- `PRD.md` 是产品目标、系统边界、冻结口径和文档分工源。
- `systems.md` 是流程、状态机、系统关系和结局读取顺序源。
- `numbers.md` 是值域、行动收益、门槛、概率、权重和结算表源。
- `content-plan.md / events.md / endings.md / question-banks.md` 是内容池、展示文本、题库、结局和成就源。
- `technical-architecture.md` 是工程实现源；它不能覆盖已确定的玩法规则。
- 表现素材与 UI 交接读取 `../asset-work/` 和 `../ui-work/`。

冲突处理按责任归位：

- 产品定位、主系统是否存在、系统边界和首版冻结范围，以 `PRD.md` 为准。
- 流程顺序、系统职责、入口可用性和结局读取流程，以 `systems.md` 为准。
- PRD 不维护具体数值；数值、阈值、倍率、概率、权重和调参目标读取 `numbers.md`。若调参会改变产品边界、核心体验或失败通关口径，先回到 PRD 口径提审。
- 事件、结局、题库和展示文案，以对应内容文档为准。
- 技术分层、存档、部署、排行榜接口和测试边界，以 `technical-architecture.md` 为准。
