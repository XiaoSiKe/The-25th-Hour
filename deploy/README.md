# 运维与本机配置

这是本项目的中文运维入口。游戏代码和素材仍使用原有路径，本次整理不改变线上部署方式。

## 先看哪一份文件

| 目的 | 入口 | 是否可以提交 Git |
|---|---|---|
| 查看操作说明、目录职责和恢复方法 | 本文 | 可以 |
| 查看环境变量名称及安全默认值 | 根目录 `.env.example` | 可以，但不得填入真实值 |
| 查看或修改本机真实令牌与运维索引 | 本机的 `deploy/运维私有配置.local.env` | 不可以，已忽略 |
| 让已有云效命令读取配置 | 根目录 `.env.local` | 不可以，已忽略 |
| 查看流水线发布及 CDN 专项操作 | `../docs/aliyun-flow-ops.md` | 可以，不写真实密钥 |

本机两个私有入口都指向同一份实际文件：

```text
$HOME/.local/share/25thgame/ops/运维私有配置.env
```

实际文件放在项目之外，权限为 `600`，父目录为 `700`。正常删除或重新克隆项目不会删除该文件；电脑或硬盘损坏仍需要独立备份。

这是带中文备注的明文环境文件，不是加密保险箱。不要发到聊天、邮件、截图、PR 或公共网盘；不要用 `git add -f` 强行加入。文件权限限制不等于加密。

## 真实凭据如何归拢

- 云效五年只读令牌、组织 ID、流水线 ID、API 地址和游戏入口保存在私有配置中；现有命令仍自动读取 `.env.local`，无需改脚本。
- SSH 私钥保留在原来的 `~/.ssh/` 文件中，私有配置只登记它的位置。不要把私钥正文复制进文档或普通环境变量。
- Cloudflare 的 OAuth 登录及刷新凭据继续由 Wrangler 管理，只登记配置文件路径，不制作会过期的手工副本。
- GitHub 登录继续由 `gh` 管理，不从登录工具或浏览器提取密码、令牌。
- 服务器上的证书、DNS 验证配置和 CDN 上传脚本只登记服务器路径，不在本次本地整理中搬动。
- 当前项目没有可归并的账号密码文件。不要把未知密码猜填进配置；账号密码建议保管在密码管理器中。

私有配置中的 `OPS_*` 字段是查找资源的索引。它们不会自动改变 SSH、Wrangler 或其他脚本的工作方式；只有云效助手目前自动加载 `.env.local`。

## 本地文件夹分工

| 位置 | 保存什么 | 整理原则 |
|---|---|---|
| `web-app/` | 可运行游戏及其资源引用 | 不随意搬动，路径属于运行契约 |
| `simulator/` | 规则回归与固定种子校验 | 保留原位 |
| `asset-work/` | 素材工程、说明和映射 | 不当作缓存删除 |
| `ui-work/` | UI 规范、交接与原型 | 不混入游戏规则文档 |
| `hyperframes/` | 动画和媒体工程 | 与运行时引用同步维护 |
| `cloudflare/` | Worker、D1 及迁移 | 不与本机凭据混放 |
| `deploy/` | 发布脚本、Nginx 配置和运维入口 | 可提交文件与私有入口分开 |
| `scripts/` | 环境、素材、验证及运维工具 | 保留调用路径 |
| `docs/` | 产品、规则和长期技术文档 | 继续遵守文档权威入口 |
| `node_modules/` | 安装的依赖 | 可由 `npm ci` 重建 |
| `.aliyun-output/` | 当前静态构建产物 | 可由构建命令重建，保留固定输出位置 |
| `.tmp/` | 工具当前输出 | 保留仍被脚本使用的报告；历史杂项归档到项目外 |

本机历史归档默认位于 `$HOME/.local/share/25thgame/archives/`，按整理时间分目录，并附文件清单与校验信息。维护前备份位于 `$HOME/.local/share/25thgame/backups/`。两者都不加入源码仓库。

## 日常检查

以下命令从项目根目录运行：

```sh
# 选择项目要求的 Node 版本并检查环境
nvm use
npm run env:check

# 读取最新流水线和运行历史，不触发部署
npm run aliyun:flow:status
npm run aliyun:flow:runs

# 本地回归检查
npm run ci:verify
```

当前五年令牌仅允许读取流水线、运行实例和运行任务。`aliyun:flow:run`、部署、数据库迁移、证书操作或资源清理都不是上述只读检查的一部分，不要为了让命令执行而扩大令牌权限。

## 删除项目或换电脑后如何恢复

同一台电脑重新克隆项目后，先确认项目外的私有文件仍然存在，再恢复入口：

```sh
# 在新克隆的项目根目录执行。已有同名文件时 ln 会失败，不要强行覆盖。
ln -s "$HOME/.local/share/25thgame/ops/运维私有配置.env" .env.local
ln -s ../.env.local deploy/运维私有配置.local.env

# 重新安装依赖并验证只读连接
nvm use
npm ci
npm run env:check
npm run aliyun:flow:status
```

新电脑需要先从安全备份恢复私有配置和必要的 SSH 私钥，按新路径更新索引；GitHub、Wrangler 可以重新登录。没有私有备份时，只能参考 `.env.example` 重建配置，并重新申请丢失的令牌。

`.env.example` 只能恢复结构，不能恢复真实密钥。不要用空模板覆盖已有私有配置，也不要把模板当作密钥备份。
